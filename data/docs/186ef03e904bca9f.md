## databricks lakewatch create-datasource

Creates a new datasource.

```
databricks lakewatch create-datasource CATALOG_NAME SCHEMA_NAME DATASOURCE_NAME SCHEDULE [flags]
```

#### Arguments

**`CATALOG_NAME`**

    Name of the Unity Catalog catalog that contains the datasource. Required on create and cannot be changed afterward. Reads return the value as supplied; the catalog's current name is reported in `effective_catalog_name`.

**`SCHEMA_NAME`**

    Name of the Unity Catalog schema that contains the datasource. Required on create and cannot be changed afterward. Reads return the value as supplied; the schema's current name is reported in `effective_schema_name`.

**`DATASOURCE_NAME`**

    Name of the datasource in Unity Catalog, unique within its schema. Required on create and can be updated within the same catalog and schema. Get synchronizes this field with the current Unity Catalog name, also reported in `effective_datasource_name`.

**`SCHEDULE`**

    Schedule on which the datasource's ingestion job runs. A datasource cannot be paused, so a request that sets `schedule.enabled` to false is rejected. Continuous schedules are not supported for Unity Catalog connection datasources.

#### Options

**`--compute-mode DatasourceComputeMode`**

    Compute mode for the datasource's ingestion job. Supported values: `DS_COMPUTE_PERFORMANCE_OPTIMIZED`, `DS_COMPUTE_STANDARD`.

**`--description string`**

    Free-form description of the datasource.

**`--json JSON`**

    Either inline JSON string or @path/to/file.json with request body.

**`--name string`**

    Resource name of the datasource, in the format `datasources/{datasource_id}`.

**`--run-as-principal string`**

    The user or service principal that the datasource runs as, given as a user email or service principal application ID.

**`--warehouse-id string`**

    ID of the SQL warehouse that runs the checks Lakewatch performs to validate a create or update request, such as source and destination access checks.

## databricks lakewatch create-parser

Creates a parser and its first version in one call.

```
databricks lakewatch create-parser CATALOG_NAME SCHEMA_NAME PARSER_NAME SPEC [flags]
```

#### Arguments

**`CATALOG_NAME`**

    Name of the Unity Catalog catalog that contains the parser. Set on create. Reads return the value as supplied; the catalog's current name is reported in `effective_catalog_name`.

**`SCHEMA_NAME`**

    Name of the Unity Catalog schema that contains the parser. Set on create. Reads return the value as supplied; the schema's current name is reported in `effective_schema_name`.

**`PARSER_NAME`**

    Name of the parser, stored as supplied and fixed at create time. Must be a valid Unity Catalog identifier. A custom parser is not a Unity Catalog securable, and it cannot be renamed.

**`SPEC`**

    Spec of version 1, as a YAML document. Only `create-parser` accepts this argument. To read a version's spec, use `get-parser-version`. See [Parser reference](/aws/en/lakewatch/ingest-data/custom-logs/parser-reference).

#### Options

**`--description string`**

    Description of version 1.

**`--json JSON`**

    Either inline JSON string or @path/to/file.json with request body.

**`--name string`**

    Resource name of the parser, in the format `parsers/{parser_id}`.

[Global flags](#global-flags)

#### Examples

The following example creates a parser named `my_parser` in the `default` schema of the `main` catalog, and returns the result as JSON:

Bash

```
databricks lakewatch create-parser main default my_parser 'fields:

- name: source_ip

type: STRING

path: src_ip

time:

coalesce:

- path: ts

' -o json
```

## databricks lakewatch create-parser-version

Appends a new immutable version to a parser and advances the parser's latest-version pointer. To edit a parser, create a new version. You can't change an existing version in place.

```
databricks lakewatch create-parser-version PARENT SPEC [flags]
```

#### Arguments

**`PARENT`**

    Resource name of the parser to add a version to, in the format `parsers/{parser_id}`.

**`SPEC`**

    The field definitions for this log source, as a YAML document. The spec is validated on write, and an invalid spec is rejected. See [Parser reference](/aws/en/lakewatch/ingest-data/custom-logs/parser-reference).

#### Options

**`--description string`**

    Free-form description of this version, set when the version is created.

**`--json JSON`**

    Either inline JSON string or @path/to/file.json with request body.

**`--name string`**

    Resource name of the version.

## databricks lakewatch create-rule

Creates a new rule.

```
databricks lakewatch create-rule CATALOG_NAME SCHEMA_NAME RULE_NAME SEVERITY FIDELITY SCHEDULE OUTPUT [flags]
```

#### Arguments

**`CATALOG_NAME`**

    Name of the Unity Catalog catalog that contains the rule. Required. Cannot be changed after creation. Reads return the value as supplied; the catalog's current name is reported in `effective_catalog_name`.

**`SCHEMA_NAME`**

    Name of the Unity Catalog schema that contains the rule. Required. Cannot be changed after creation. Reads return the value as supplied; the schema's current name is reported in `effective_schema_name`.

**`RULE_NAME`**

    Name of the rule within its Unity Catalog schema. Required on create; can be updated within the same catalog and schema. Get synchronizes this field with the current Unity Catalog name, also reported in `effective_rule_name`.

**`SEVERITY`**

    Free-form severity label, such as Informational, Medium, High, or Critical.

**`FIDELITY`**

    Signal quality for this rule. Supported values: [FIDELITY\_DEVELOPMENT, FIDELITY\_HIGH, FIDELITY\_INVESTIGATIVE, FIDELITY\_MEDIUM].

**`SCHEDULE`**

    When the rule executes.

**`OUTPUT`**

    What to record in each signal.

#### Options

**`--category string`**

    Free-form rule category.

**`--content-resource-id string`**

    Immutable UUIDv4 identifying the authored content resource installed as this rule.

**`--deduplication RuleDeduplication`**

    Signal deduplication mode. Supported values: `DEDUPLICATION_DEFAULT`, `DEDUPLICATION_DISABLED`, `DEDUPLICATION_ENABLED`.

**`--deduplication-time-window string`**

    Time window for deduplication, such as 1h, 24h, 7d, or automatic.

**`--description string`**

    Free-form description.

**`--json JSON`**

    Either inline JSON string or @path/to/file.json with request body.

**`--name string`**

    Resource name, in the form `rules/{rule_id}`.

**`--objective string`**

    Long-form description of what this rule detects.

**`--run-as-principal string`**

    The principal whose identity this rule's job runs as, given as a user email or service-principal application ID.

**`--runbook string`**

    Long-form operational guidance carried from the authored rule metadata.

**`--suppress-until-time string`**

    If set, this rule's signals do not open new alerts until the given time.

## databricks lakewatch delete-parser-version

Deletes one version of a parser. Returns `NOT_FOUND` when the parser or the version does not exist, and a conflict (HTTP 409) only while a datasource references the version. Deleting the last version leaves the parser in place with no versions.

```
databricks lakewatch delete-parser-version NAME [flags]
```

#### Arguments

**`NAME`**

    Resource name of the version, in the format `parsers/{parser_id}/versions/{version}`, where `{version}` is a version number written without a sign or leading zeros, such as `3`. Unlike `get-parser-version`, this command rejects the alias `latest` and forms such as `007` or `+3`, so each delete targets one fixed version.

## databricks lakewatch list-builtin-parsers

Lists the built-in parsers that Databricks publishes, without their specs.

```
databricks lakewatch list-builtin-parsers [flags]
```

#### Options

**`--filter string`**

    Filter expression that restricts the results by tag. Supports a single clause, either `tags.<key> = "<value>"` to match a tag value or `tags.<key>:*` to match any parser that has the tag. Quote a key that contains a dot, for example `tags."lw.vendor"
