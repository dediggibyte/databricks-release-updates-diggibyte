This page provides information about how to define job tasks in Declarative Automation Bundles. For information about job tasks, see [Configure and edit tasks in Lakeflow Jobs](/aws/en/jobs/configure-task).

important

The job `git_source` field and task `source` field set to `GIT` are not recommended for bundles, because local relative paths may not point to the same content in the Git repository. Bundles expect that a deployed job has the same files as the local copy from where it was deployed.

Instead, clone the repository locally and set up your bundle project within this repository, so that the source for tasks are the workspace.

## Configure tasks

Define tasks for a job in a bundle in the `tasks` key for the job definition. Examples of task configuration for the available task types is in the [Task settings](#task-settings) section. For information about defining a job in a bundle, see [job](/aws/en/dev-tools/bundles/resources#jobs).

tip

To quickly generate resource configuration for an existing job using the [Databricks CLI](/aws/en/dev-tools/cli/), you can use the `bundle generate job` command. See [bundle commands](/aws/en/dev-tools/cli/bundle-commands#generate).

To set task values, most job task types have task-specific parameters, but you can also define [job parameters](/aws/en/jobs/job-parameters) that get passed to tasks. [Dynamic value references](/aws/en/jobs/dynamic-value-references) are supported for job parameters, which enable passing values that are specific to the job run between tasks. For complete information on how to pass task values by task type, see [Details by task type](/aws/en/jobs/parameter-use#details-by-task-type).

You can also override general job task settings with settings for a target workspace. See [Override with target settings](/aws/en/dev-tools/bundles/overrides).

The following example configuration defines a job with two notebook tasks, and passes a task value from the first task to the second task.

YAML

```
resources:

jobs:

pass_task_values_job:

name: pass_task_values_job

tasks:

# Output task

- task_key: output_value

notebook_task:

notebook_path: ../src/output_notebook.ipynb

# Input task

- task_key: input_value

depends_on:

- task_key: output_value

notebook_task:

notebook_path: ../src/input_notebook.ipynb

base_parameters:

received_message: '{{tasks.output_value.values.message}}'
```

The `output_notebook.ipynb` contains the following code, which sets a task value for the `message` key:

Python

```
# Databricks notebook source

# This first task sets a simple output value.

message = "Hello from the first task"

# Set the message to be used by other tasks

dbutils.jobs.taskValues.set(key="message", value=message)

print(f"Produced message: {message}")
```

The `input_notebook.ipynb` retrieves the value of the parameter `received_message`, that was set in the configuration for the task:

Python

```
# This notebook receives the message as a parameter.

dbutils.widgets.text("received_message", "")

received_message = dbutils.widgets.get("received_message")

print(f"Received message: {received_message}")
```

## Task settings

This section contains settings and examples for each job task type.

### AI Function task

Beta

The AI Function task, including support in Declarative Automation Bundles, is in [Beta](/aws/en/release-notes/release-types). Workspace admins can control access to the AI Function task from the **Previews** page. See [Manage Databricks previews](/aws/en/admin/workspace-settings/manage-previews).

The AI Function task runs an AI function on every file in a Unity Catalog volume or every row of a table, and writes the results to a Unity Catalog table, when the `ai_function_task` field is present. Each run processes only the files or rows that were added, changed, or deleted since the previous run. For more information about AI Function tasks, see [AI Function tasks for jobs](/aws/en/jobs/tasks/ai-functions/).

The following keys are available for an AI Function task. Set one input, `volume` or `delta_table`, and one function, `ai_parse_document`, `ai_extract`, or `ai_classify`. For the corresponding REST API object definition, see [ai\_function\_task](https://docs.databricks.com/api/workspace/jobs/create#tasks-ai_function_task).

*Added in Databricks CLI version 1.24.0*

| `ai_classify` | Map | Classifies each row into labels you define. See [`ai_classify` task for jobs](/aws/en/jobs/tasks/ai-functions/classification). Contains:   * `version` (String): Required. The `ai_classify` version to run, for example `2.1`. * `inline_labels` (Map): Required. The labels. Contains `labels` (Sequence), where each label has a `name` (String) and an optional `description` (String). An `ai_classify` task takes 2 to 10 labels, or 1 to 10 if `multilabel` is `true`. * `instructions` (String): Guidance applied to every row. * `multilabel` (Boolean): Whether more than one label can be assigned to each input. * `enable_confidence_scores` (Boolean): Whether to include a confidence score for each label. * `enable_rationales` (Boolean): Whether to include a rationale for each classification. |

Contains:   * `version` (String): Required. The `ai_extract` version to run, for example `2.1`. * `schema` (String): The fields to extract, as a JSON string in the format that [`ai_extract`](/aws/en/sql/language-manual/functions/ai_extract#arguments) expects. * `instructions` (String): Guidance applied to every field. * `mode` (String): Set to `MODE_PRECISION` to improve accuracy for complex fields and long documents. The `ai_parse_document` output schema version, for example `2.0`. * `description_element_types` (Sequence): The element types to generate AI descriptions for. Set `DESCRIPTION_ELEMENT_TYPE_ALL` for all supported types or `DESCRIPTION_ELEMENT_TYPE_FIGURE` for figures only. If you leave this out, the task generates no descriptions. * `image_output_path` (String): A volume path where rendered page and element images are written. |
| `delta_table` | Map | A Unity Catalog table input. The function runs on each row. The table must have [change data feed](/aws/en/tables/features/change-data-feed) enabled. Contains:   * `table_name` (String): Required. The three-part name of the table, or a reference to an earlier task's output table such as `{{tasks.<task_key>.output.table_name}}`. * `input_column` (String): Required. The column that holds the content to run the function on. * `merge_key_columns` (Sequence): The columns that identify a row across runs, such as a primary key. If you leave this out, the task uses the file's URI for a `FILE` column, or otherwise the table's [row tracking](/aws/en/tables/features/row-tracking) ID, which requires row tracking to be enabled on the table. See [ID column](/aws/en/jobs/tasks/ai-functions/#id-column). |
| `output` | Map | Required. The output table. The task creates and manages this table. Contains:   * `catalog` (String): The catalog of the output table. * `schema` (String): The schema of the output table. The schema must already exist. * `table` (String): The name of the output table. If you leave this out, the task generates a name that stays the same across runs. |
| `volume` | Map | A Unity Catalog volume input. The function runs on each file. Contains:   * `volume_path` (String): Required. The path to a volume or a folder in a volume, for example `/Volumes/main/finance/invoices`. |

#### Examples

The following example adds an `ai_parse_document` task to a job. The task parses each file in a volume and generates descriptions for figures only.

YAML

```
resources:

jobs:

parse_invoices:

name: parse_invoices

tasks:

- task_key: parsing

ai_function_task:

volume:

volume_path: /Volumes/main/finance/invoices

output:

catalog: main

schema: finance

ai_parse_document:

version: '2.0'

description_element_types: [DESCRIPTION_ELEMENT_TYPE_FIGURE]
```

The following example parses the files in a volume and then extracts an invoice ID and a total from each parsed document. The `extraction` task reads the `parsing` task's output table with `{{tasks.parsing.output.table_name}}`, reads its `response` column, and uses its `id` column to identify rows. To classify the parsed documents instead, replace the `ai_extract` function with an `ai_classify` function, like the one in the `ai_classify` example, and set `output.table` to a new name such as `invoice_labels`. See [Use the output in a later task](/aws/en/jobs/tasks/ai-functions/#chain).

YAML

```
resources:

jobs:

parse_and_extract_invoices:

name: parse_and_extract_invoices

tasks:

- task_key: parsing

ai_function_task:

volume:

volume_path: /Volumes/main/finance/invoices

output:

catalog: main

schema: finance

ai_parse_document:

version: '2.0'

- task_key: extraction

depends_on:

- task_key: parsing

ai_function_task:

delta_table:

table_name: '{{tasks.parsing.output.table_name}}'

input_column: response

merge_key_columns: [id]

output:

catalog: main

schema: finance

table: invoice_fields

ai_extract:

version: '2.1'

schema: |

{

"invoice_id": {"type": "string", "description": "Unique invoice identifier"},

"total_amount": {"type": "number", "description": "Total invoice amount"}

}
```
