A custom Python service policy is a Python function registered in Unity Catalog that decides whether each request or response to an AI service is allowed. Use Python when a rule is hard to express in SQL, when it needs a Python library, or when it needs to call another service, such as a guardrail service you already use.

You attach a Python policy to a Model Service, Model Provider Service, or MCP Service, the same way you attach any [service policy](/aws/en/data-governance/unity-catalog/service-policies/).

## When to use a Python policy

Choose the simplest policy type that expresses your rule:

* A [built-in guardrail](/aws/en/data-governance/unity-catalog/service-policies/create-service-policy#use-a-built-in-policy) covers common risks, such as unsafe content and sensitive data, with no code.
* A [custom LLM-as-a-judge policy](/aws/en/data-governance/unity-catalog/service-policies/create-service-policy#create-an-llm-as-a-judge-policy) handles semantic rules you can describe in plain language.
* A [custom SQL policy](/aws/en/data-governance/unity-catalog/service-policies/create-service-policy#create-a-sql-policy) handles simple deterministic checks on fields such as the tool name or the caller's identity.
* An [external service policy](/aws/en/data-governance/unity-catalog/service-policies/external-policies) enforces a guardrail vendor that implements the Databricks external policy API.

Use a Python policy for logic the other types can't express. Common uses include:

* **Keyword and pattern filtering**: block requests or responses that match regular expressions, such as internal hostnames, ticket IDs, or credential formats.
* **Custom sensitive data checks**: detect identifiers specific to your organization, such as employee or customer numbers, that the built-in Sensitive Data Detection policy doesn't cover.
* **Tool argument validation**: check MCP tool call arguments in detail, for example to allow a write only to approved repositories or paths.
* **Python packages**: use a package from PyPI, such as a parser or a classifier. See [Add Python packages](#add-python-packages).
* **Calls to a partner guardrail or internal service**: call an external service, such as a guardrail, with a Unity Catalog service credential, then return its verdict. See [Call an external service with a service credential](#call-an-external-service-with-a-service-credential).

## Availability

Custom Python service policies are in Beta and are available in the following regions:

* `us-east-1`
* `us-west-2`

Custom Python service policies aren't available in other regions.

## How a Python policy works

A Python policy is a [Unity Catalog Python UDF](/aws/en/udf/unity-catalog) with a fixed signature. It takes two `VARIANT` parameters and returns a `VARIANT`:

SQL

```
CREATE OR REPLACE FUNCTION <catalog>.<schema>.<function_name>(

event VARIANT,

config VARIANT

)

RETURNS VARIANT

LANGUAGE PYTHON

ENVIRONMENT (environment_version = '6')

AS $$

<function body>

$$;
```

* `event` is the interaction under evaluation. It has the same fields as the event a SQL policy receives, such as `type` (`request` or `response`), `context.message` (the latest user or assistant message), `context.tool.name` and `context.tool.arguments` on an MCP Service, and the caller's identity in `context.actor`. See [Event fields](/aws/en/data-governance/unity-catalog/service-policies/policy-function-reference#the-event-argument).
* `config` holds the options stored on the policy's attachment, or an empty object when it has none. Your function must declare it, even if it doesn't use it.
* The function returns a decision: `ALLOW`, `DENY`, or `ASK`, with an optional `reason`. `ASK` holds an MCP tool call for human approval on the request phase. On an MCP tool result, `ASK` lets the result through, so return `DENY` to block it. On a Model Service or Model Provider Service, `ASK` blocks the interaction, and the caller sees a message that `ASK` isn't supported instead of your `reason`, so return `DENY` there.

Databricks runs the function on serverless compute that it manages, not on your SQL warehouse or cluster. The function runs at both evaluation points, the request (input) and the response (output), so branch on `type` to act on one phase. If the function raises an error, times out, or returns an unrecognized decision, Databricks denies the interaction.

## Before you begin

* The **Unity Gateway Service Policies** preview must be turned on for your workspace. A workspace admin turns it on from the **Previews** page. See [Manage workspace-level previews](/aws/en/admin/workspace-settings/manage-previews#workspace).
* The workspace that sends requests to the service must be in a [supported region](#availability). In other regions, a Python policy denies every interaction it evaluates in **Enforce** mode. In **Log** mode, the interaction proceeds and the would-be denial is recorded.
* The workspace that sends requests to the service must not use the [compliance security profile](/aws/en/security/privacy/security-profile), a [serverless network policy](/aws/en/security/network/serverless-network-security/network-policies) that restricts internet access or blocks specific destinations, or a [private network gateway](/aws/en/security/network/serverless-network-security/private-network-gateway). In these workspaces, a Python policy denies every interaction it evaluates in **Enforce** mode. In **Log** mode, the interaction proceeds and the would-be denial is recorded. The check applies to the workspace that sends the request, not the workspace where you attach the policy.
* To create the function: `USE CATALOG` and `USE SCHEMA` on the target catalog and schema, and `CREATE FUNCTION` on the schema.
* To attach the policy: `MANAGE` on the target service and `EXECUTE` on the function. Callers of the service don't need `EXECUTE` on the function.
* To call an external cloud service from the function: a [Unity Catalog service credential](/aws/en/connect/unity-catalog/cloud-services/service-credentials) for that service, and `ACCESS` on the credential to create a function that declares it.
* To read a secret from the function: a [Unity Catalog secret](/aws/en/udf/unity-catalog#uc-secrets).

## Create a Python policy in the policy form

You can write, check, and test the function without leaving the policy form.

1. In the workspace sidebar, click **Unity Gateway**.
2. Select the service to govern: a model service on the **Models** tab, a model provider service on the **Providers** tab, or an MCP service on the **MCPs** tab.
3. Open the **Policies** tab, then click **New policy**.
4. Enter a **Name** for the policy.
5. In **Guardrail type**, select **Custom**.
6. Set the **Rank** to control evaluation order. The lowest rank runs first on the request and last on the response.
7. Under **Implementation**, select **Custom function**.
8. Under **Function**, select **Create new**. In **Compute for creating the function and testing**, select a SQL warehouse. Databricks uses it only to create the function and run tests, not to evaluate live traffic.
9. Select **Python**. To start from a template, select one, such as **Block unsafe output** or **Block prompt injection**.
10. In **Function name**, enter the full name, for example `main.governance.block_internal_hosts`.
11. In **Dependencies (optional)**, list the Python packages the function needs that aren't already in the environment, one per line, for example `phonenumbers`. Databricks adds them to the function's `ENVIRONMENT` clause.
12. (Optional) To use a secret or a service credential, expand **Secrets and credentials (optional)**:

    * In **Secrets (optional)**, list the Unity Catalog secrets the function reads, one per line, for example `main.default.api_key`.
    * In **Default credential (optional)**, select the service credential the function uses. To add more credentials, click **Add**, then select each credential and give it an **Alias**.

    Databricks adds them to the function's `SECRETS` and `CREDENTIALS` clauses. See [Use a secret](#use-a-secret) and [Call an external service with a service credential](#call-an-external-service-with-a-service-credential).
13. Write the function body in the editor, then click **Check syntax**.
14. Expand **Test function**. Under `event`, insert a sample event. On a Model Service or Model Provider Service, click **Request** or **Response**. On an MCP Service, select a tool in **Select tool** to insert a tool call with that tool's arguments. Edit the event to match the case you want to test. Leave `config` as `{}`. Click **Run test**. **Returns** shows the decision, and the reason when there is one.
15. Click **Create policy**.

The function is created in Unity Catalog and the policy appears on the service's **Policies** tab. The function's dependencies install the first time the policy runs, and the policy denies interactions until the installation finishes. See [Performance](#performance). To reuse a function you already created, select **Select existing** under **Function** instead of **Create new**.

## Create a Python policy with SQL

You can also create the function with `CREATE FUNCTION` in a notebook or the SQL editor, then attach it with **Select existing** in the policy form.

The following function runs on a Model Service or Model Provider Service. It blocks responses that contain an internal hostname or an access key pattern. It reads the message from `context.message` and returns a decision built by the `policy_decision` helper:

SQL

```
CREATE OR REPLACE FUNCTION main.governance.block_internal_hosts(

event VARIANT,

config VARIANT

)

RETURNS VARIANT

LANGUAGE PYTHON

ENVIRONMENT (environment_version = '6')

AS $$

import json

import re

def policy_decision(result, reason=""):

return type(event).parseJson(json.dumps({"decision": {"result": result, "reason": reason}}))

event_value = event.toPython() if hasattr(event, "toPython") else event

if event_value.get("type") != "response":

return policy_decision("ALLOW")

message = str(event_value.get("context", {}).get("message", ""))

patterns = {

"an internal hostname": r"\b[a-z0-9-]+\.corp\.example\.com\b",

"an access key": r"\bAKIA[0-9A-Z]{16}\b",

}

for label, pattern in patterns.items():

if re.search(pattern, message, flags=re.IGNORECASE):

return policy_decision("DENY", f"The response contains {label}.")

return policy_decision("ALLOW")

$$;
```

To attach it, follow [Create a Python policy in the policy form](#create-a-python-policy-in-the-policy-form), but select **Select existing** under **Function** and choose the function.

## Write the function

### Read the event

The `event` and `config` parameters are `VARIANT` values. Convert `event` to a Python dictionary with `toPython()`, then read fields with `get()`, so a missing field doesn't raise an error:

Python

```
event_value = event.toPython() if hasattr(event, "toPython") else event

phase = event_value.get("type")                                  # "request" or "response"

message = event_value.get("context", {}).get("message", "")      # latest user or assistant message

tool = event_value.get("context", {}).get("tool", {})            # MCP Services only
```

For the full list of fields, see [Event fields](/aws/en/data-governance/unity-catalog/service-policies/policy-function-reference#the-event-argument).

### Return a decision

Return a `VARIANT` that holds a `decision` object with a `result` of `ALLOW`, `DENY`, or `ASK` and an optional `reason`. The `result` is case-insensitive. Build the return value from a dictionary with `type(event).parseJson()`:

Python

```
import json

def policy_decision(result, reason=""):

return type(event).parseJson(json.dumps({"decision": {"result": result, "reason": reason}}))

return policy_decision("DENY", "The response contains an internal hostname.")
```

If the function returns `DENY` without a `reason`, or with an empty one, the caller sees the default reason: `Access denied: this request is not permitted by a policy on this service.`

When the policy denies an interaction on a Model Service or Model Provider Service, the caller receives the `reason` in the `databricks_service_policy` object. On an MCP Service, the caller receives a JSON-RPC error with the `reason` in `error.message`. See [Policy decisions](/aws/en/data-governance/unity-catalog/service-policies/#policy-decisions).

### Add Python packages

To use a package that isn't in the environment, list it in **Dependencies (optional)** in the policy form, or declare it in the `dependencies` option of the `ENVIRONMENT` clause when you create the function with SQL. Keep `environment_version = '6'`:

SQL

```
ENVIRONMENT (

dependencies = '["phonenumbers"]',

environment_version = '6'

)
```

Packages that are already in [environment version 6](/aws/en/release-notes/serverless/environment-version/six), such as `boto3` and `requests`, don't need to be listed. Dependencies are installed from PyPI. See [Extend UDFs using custom dependencies](/aws/en/udf/unity-catalog#custom-dependencies).

```
