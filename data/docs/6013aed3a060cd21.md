*Parameters* in Lakeflow Designer are named values defined for the visual data prep as a whole. You can reference parameters in SQL and Python operator code, in supported operator configuration fields, and in expressions that enable or disable operators. Parameters let you run the same visual data prep against different environments, for example, a test catalog during development and a production catalog in production.

## Requirements

* To create parameters or change field bindings, you must have permission to edit the visual data prep.
* To parameterize a group, you must have permission to
  + edit the visual data prep
  + run previews

## Define parameters

To manage parameters, select **Parameters** in the [left pane](/aws/en/designer/interface#left-pane). Each parameter has a value that you set when you define it. When the visual data prep runs on a schedule or as a job, you can override that value. See [Override parameter values in production](#override).

The panel lists the operators that use each parameter. Select an operator name to focus it on the canvas.

## Reference a parameter from an operator

How you reference a parameter depends on where you use it:

* **SQL operator**: Use named parameter marker syntax, such as `:environment`. See [Use named parameter markers](/aws/en/sql/user/queries/query-parameters).
* **Python operator**: Call `dbutils.widgets.get()`, such as `dbutils.widgets.get("environment")`. See [Widgets tool (dbutils.widgets)](/aws/en/dev-tools/databricks-utils#dbutils-widgets).
* **Supported operator configuration fields**: Hover over the field in the operator's configuration pane, then select  (**Use a parameter**). Enter an expression such as `:source_table`, or select an existing parameter. Supported fields include:
  + **Source**: **Table**, **File path**, and **File format**.
  + **Output**: **Catalog**, **Schema**, **Table**, **View**, **Volume**, **File name**, and **Write mode**.
  + **Limit**: **Limit**.
  + **Filter**: Individual condition expressions.
  + **Prepare**: Supported fields within individual actions.
  + **Combine**: **Set operation**, **Merge strategy**, **Union by name**, and **Allow missing columns**.

To define a parameter while configuring a supported field, select **Create parameter** in the parameter picker. Configure the new parameter in the **Parameters** pane, then use it in the field.

When you open a SQL or Python operator for editing, Lakeflow Designer shows an example of how to reference the available parameters above the source editor.

## Combine parameters with fixed text

In a parameter expression for a Source or Output operator, use `:parameter_name` to replace an entire value. To combine parameters with fixed text, enclose the text in single quotes and use `||`. For example, the following Source **Table** expression constructs a fully qualified table name:

SQL

```
:catalog || '.' || :schema || '.' || :table
```

## Enable or disable an operator with a parameter

To control whether a configured operator runs:

1. Open the operator's configuration pane and select  (**Operator settings**).
2. Next to **Disabled**, select  (**Use a parameter**).
3. Enter a Boolean expression, such as `:skip_operator`.

The expression disables the operator when it evaluates to True. A disabled operator produces no output rows.

To control an entire group, open **Disable group** or **Enable group** in the group's toolbar, then select  (**Use a parameter**) next to **Disabled**. Enter a Boolean expression and close the editor to apply it.

To enable or disable an operator manually instead, see [Rename, copy, delete, and disable operators](/aws/en/designer/interface#operator-actions).

## Override parameter values in production

At runtime, a visual data prep reads its parameters the same way whether it runs interactively or as a job, so the same file works across all of your environments without changes. Supply different values for each environment as follows:

* **When you schedule a job in the UI**: Override the parameter values for each schedule. For example, schedule the same visual data prep to run every day at noon with an `environment` parameter set to `test`, and again at 2 PM with `environment` set to `production`. See [Schedule as a job](/aws/en/designer/production#schedule).
* **When you deploy with a bundle**: Set the parameter values through the job's `parameters`, and use bundle targets to supply different values per environment. Bundle development and production targets let you deploy the same job to separate environments with environment-specific settings. See [Declarative Automation Bundles deployment modes](/aws/en/dev-tools/bundles/deployment-modes) and [Declarative Automation Bundles configuration](/aws/en/dev-tools/bundles/settings).
