Beta

This feature is in [Beta](/aws/en/release-notes/release-types). To use it, a workspace admin must turn on **Lakeflow Connect for Okta System Logs** from the **Previews** page. See [Manage Databricks previews](/aws/en/admin/workspace-settings/manage-previews).

The managed Okta System Logs connector in Lakeflow Connect ingests audit and security events from your Okta organization into Databricks.

The connector uses the [Okta System Log API](https://developer.okta.com/docs/api/openapi/okta-management/management/systemlog) to ingest append-only events, including user activity, authentication, security, and configuration changes.

## Start ingesting from Okta

1. **[Configure Okta for ingestion](/aws/en/ingestion/lakeflow-connect/okta-system-logs-source-setup)** (Okta admins). Create an SSWS API token for Databricks.
2. **[Create a Unity Catalog connection](/aws/en/ingestion/lakeflow-connect/okta-system-logs-connection)** (Admins). Create a connection in Catalog Explorer so pipeline authors don't need direct access to the API token.
3. **[Create an ingestion pipeline](/aws/en/ingestion/lakeflow-connect/okta-system-logs-pipeline)** (Admins or non-admins). Use Declarative Automation Bundles or a Databricks notebook to create a pipeline from an existing connection.
