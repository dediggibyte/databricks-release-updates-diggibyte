This article explains how to use budgets to track spending in your Databricks account.

Budgets enable you to monitor usage across your account. You can set up budgets to either track account-wide spending, or apply filters to track the spending of specific teams, projects, or workspaces. For budgets scoped to Unity Gateway, you can track spend against per-user thresholds.

Budgets are measured in USD and use the list price of the SKU, including platform add-ons.

## Requirements

* You must be an account admin to create and manage budgets.
* Workspace admins can create and manage budgets scoped to workspaces they administer using [Governance Hub](/aws/en/admin/governance-hub/).

To let other users view or manage a budget, grant them a budget role. See [Manage budget permissions](/aws/en/admin/account-settings/budget-permissions).

## Create a budget

1. In the [account console](https://accounts.cloud.databricks.com) sidebar, click **Usage**.
2. Click the **Budgets** tab then click **Add budget**.
3. Enter a **Name** for your budget.
4. In the **Definitions** section you can limit the budget's tracked spending based on product, workspace, and custom tags. If you leave these fields blank, your budget will measure usage across your whole account.

   1. In the **Workspaces** drop-down, select the workspaces you would like to include in your budget. Leave the field empty to track your entire account's usage.
   2. In the **Resource types** drop-down, select **All** to track spend across every Databricks product, or **Unity Gateway** to track only spend through Unity Gateway endpoints.
   3. (Optional) In the **Resource tags** section, you can scope the budget to a selection of custom tags. If you add tags to this section, the budget will only track usage that includes the specified custom tags. For Unity Gateway budgets, tags are matched against endpoint tags.

      warning

      Tag data is stored as plain text and may be replicated globally. Do not use tag names, values, or descriptors that could compromise the security of your resources. For example, do not use tag names, values or descriptors that contain personal or sensitive information.
5. Create up to four shared thresholds, which monitor monthly spend against a specified threshold. For each threshold:

   1. Click the **Add threshold** button.
   2. Enter a dollar amount in the **Monthly threshold** field.
   3. (Optional) Check **Send email** and enter a comma-separated list of email addresses. These addresses receive alerts when spending exceeds the threshold. If you don't send email, you can still track the budget in the account console.
   4. (Optional) Check **Block usage** to prevent users from making further requests through Unity Gateway when the threshold is reached. Only one shared threshold can block usage, and it must be the highest shared threshold.
   5. (Optional) Check **Trigger webhook** and select one or more destinations to send a webhook payload when the threshold is reached. See [Trigger custom webhooks](#trigger-custom-webhooks).
   6. Click **Add**.
6. (Budgets for Unity Gateway only) Optionally configure a **Per-user spend threshold**. This threshold tracks individual Unity Gateway usage within the budget. When a per-user threshold is crossed, an alert is sent out and usage can optionally be blocked. This threshold is the default for each user in the account. To set a higher limit for specific users or groups, configure per-user overrides later in these steps.

   1. Enter a dollar amount in the **Monthly threshold** field. Each user gets their own copy of the threshold, which applies to their Unity Gateway requests that fall within the budget's scope.
   2. (Optional) Check **Send email** and enter a comma-separated list of email addresses. These addresses receive alerts when a user's spending exceeds the threshold. The notification identifies the user, their month-to-date spend, and the budget.
   3. (Optional) Check **Block usage** to prevent the user from making further requests through Unity Gateway when the threshold is reached.
   4. (Optional) Check **Trigger webhook** and select one or more destinations to send a webhook payload when a user reaches the threshold. See [Trigger custom webhooks](#trigger-custom-webhooks).

      important

      Budget email notifications and webhook payloads include the budget name, workspace filter, user identity for per-user thresholds, and defined custom tags. Email recipients do not need to be Databricks users, and webhook destinations can be external endpoints. Ensure you are protecting sensitive data when naming the budget, selecting tags, adding email recipients, and choosing webhook destinations.
7. (Optional) Configure **Per-user overrides** to grant specific users or groups a higher spending limit than the default per-user threshold. Users covered by an override spend up to the override amount rather than the default per-user limit. If a user belongs to multiple override groups, the highest threshold applies.
8. Click **Create**.

## Trigger custom webhooks

Beta

This feature is in [Beta](/aws/en/release-notes/release-types). Account admins can manage access to this feature from the account console **Previews** page. See  [Manage account-level previews](/aws/en/admin/workspace-settings/manage-previews#account).

A budget threshold can send an HTTP POST request to a webhook when it's reached, so you can route budget events to incident management, ticketing, or automation tools. To use this feature, an account admin must turn on the **Account-level Webhook Destinations** preview.

Budget webhooks use account-level notification destinations. Account admins create these destinations in the account console. After a destination is created, any user in the account can view it and select it as a threshold action. Account-level notification destinations support webhooks only. Workspace-level notification destinations can't be used in budgets.

### Create a webhook destination

You must be an account admin to create a webhook destination.

1. Open the notification destinations page in the account console.

   Go directly to the [notification destinations page](https://accounts.cloud.databricks.com/settings/notifications), or:

   1. In the [account console](https://accounts.cloud.databricks.com) sidebar, click **Settings**.
   2. Click the **Notifications** tab.
2. Click **Add destination**.
3. Enter a **Name** and the webhook **URL**. The URL must use HTTPS.
4. (Optional) Enter a **Username** and **Password** to authenticate requests with HTTP basic authentication.
5. Click **Create**.

Account-level webhook destinations work like workspace-level webhook destinations. See [Manage notification destinations](/aws/en/admin/workspace-settings/notification-destinations).

### Webhook payload

When a budget threshold with **Trigger webhook** enabled is reached, Databricks sends a JSON payload to each selected destination. The payload includes the budget, the threshold (`quantity_threshold`), the near real-time spend (`current_spend`), and an `event_id` you can use to discard duplicate deliveries. For per-user thresholds, the payload also includes the `principal_id` and `user_name` of the user who reached the threshold, and the threshold and spend values are that user's.

The following example shows a payload for a shared threshold. Amounts are decimal strings in US dollars at list price, and times are RFC 3339 timestamps in UTC.

JSON

```
{

"event_type": "budgets.on_threshold_exceeded",

"event_id": "<event-id>",

"schema_version": "1",

"account_id": "<account-id>",

"budget": {

"budget_configuration_id": "<budget-id>",

"display_name": "ML team AI Gateway budget",

"resource_type": "BUDGET_RESOURCE_TYPE_UNITY_AI_GATEWAY",

"filter": {

"workspace_id": { "operator": "IN", "values": [1234567890123456] },

"tags": [{ "key": "team", "value": { "operator": "IN", "values": ["ml"] } }]

}

},

"alert": {

"alert_configuration_id": "<alert-configuration-id>",

"scope_type": "ALERT_CONFIGURATION_SCOPE_TYPE_SHARED",

"time_period": "MONTH",

"trigger_type": "CUMULATIVE_SPENDING_EXCEEDED",

"quantity_type": "LIST_PRICE_DOLLARS_USD"

},

"evaluation": {

"evaluated_at": "2026-10-12T00:00:00Z",

"quantity_threshold": "50.00",

"current_spend": "50.02",

"period": {

"start": "2026-10-01T00:00:00Z",

"end": "2026-11-01T00:00:00Z"

}

}

}
```

For a per-user threshold, `scope_type` is `ALERT_CONFIGURATION_SCOPE_TYPE_PER_USER` and the payload adds a `principal` object:

JSON

```
{

"principal": {

"principal_id": 1234567890,

"user_name": "user@example.com"

}

}
```

## What a Unity Gateway budget covers

When you scope a budget to the **Unity Gateway** product, the budget tracks all spend associated with [Unity Gateway](/aws/en/ai-gateway/) endpoints defined in the scope. This covers [Pay-Per-Token](/aws/en/machine-learning/foundation-model-apis/) (also called pay-as-you-go), [ai\_query](/aws/en/sql/language-manual/functions/ai_query) (batch) inference, and optional external model usage through [model provider services](/aws/en/ai-gateway/model-provider-services).

Endpoint and Unity Catalog tags are respected. If you add a tag filter to the budget (for example, `team=ml-platform`), only Unity Gateway endpoints carrying that tag count toward the budget. Request tags don't affect budget matching.

Provisioned throughput inference requests are not tracked by Unity Gateway budgets.

For deeper cost analysis of Unity Gateway spend, including dashboards and usage details, see [Analyze Unity Gateway cost](/aws/en/ai-gateway/cost-observability).

Account and workspace admins can view a summary of budget status and overall spend on the [Cost page](/aws/en/admin/governance-hub/cost) in Governance Hub.

For budgets that track Genie usage, see [Manage budgets and cost controls for Genie](/aws/en/genie/budgets).

## View budget details

You can use email notifications to learn when monthly spending has surpassed your budget.

You can also track the status of a budget by clicking the budget name in the account console. The budget details page displays the current month's spend, the remaining budget, and a visualization of the day-to-day cumulative spend. Alert thresholds appear as dotted lines on the chart.

For budgets scoped to Unity Gateway, the budget details page also shows a per-user spend table. The table lists every user who has Unity Gateway usage within the budget scope, their month-to-date spend, and their status against the per-user threshold (under, approaching, or exceeded).

## Update or delete a budget

To update or delete a budget, click the  kebab menu in the rightmost column of the budget's row and select **Edit budget** or **Delete budget**.

## Monitor serverless compute budgets

If your account uses serverless compute, you can use serverless usage policies to attribute your account's serverless usage. See [Attribute usage with serverless usage policies](/aws/en/admin/usage/budget-policies).

For more information about serverless compute usage monitoring, see [Monitor the cost of serverless compute](/aws/en/admin/system-tables/serverless-billing).

## Known limitations

important

Budgets for Unity Gateway provide a near real-time estimate of the spend tracked against the configured thresholds, and actual costs incurred may differ from configured thresholds. This feature is intended to help with near real-time cost control. Do not use this feature as a way to ensure an absolute spend cap on final billed amounts. Databricks is not responsible for costs incurred in excess of configured budget thresholds.

* You can configure a maximum of four shared thresholds per budget. Each shared threshold must have a unique monthly threshold value. Budgets for Unity Gateway can also have one default per-user spend threshold, which doesn't count toward this limit. Per-user overrides for specific users or groups must be higher than the default per-user threshold.
* Only one shared threshold per budget can block usage, and it must be the threshold with the highest value.
* Your account can have a maximum of 1,000 budgets.
* There could be up to a 24-hour delay between usage occurring and an email notification being sent. For [Unity Gateway budgets](/aws/en/ai-gateway/budgets), this delay is considerably shorter and near real-time.
* After you create a new budget, there could be a delay before you can see the budget details.
* Budget webhooks aren't available in government or regulated environments.
* Budgets do not factor in any billing credits or negotiated discounts your account might have. The spent amount is calculated by multiplying usage by the SKU list price.
* **Block usage thresholds are enforced approximately.** Enforcement uses a near-real-time estimate of cost, so actual spend may vary above or below the configured threshold. This means:

  + A user may be blocked before their actual spend reaches the threshold.
  + An amount of spend over the threshold may occur before enforcement takes effect. Active requests in progress when the threshold is reached are not interrupted.

  `system.billing.usage` remains the source of truth for actual billable usage. For discrepancies between usage tracked against a budget and actual costs, Databricks may retroactively adjust budget estimates to reconcile them.
* Spend amounts in the budget alert emails, budget details page, and `system.billing.usage` may differ when compared at the same point in time. This is expected, because each source updates at a different rate:

  + **Budget alert emails**: Reflect spend at the moment the alert was triggered.
  + **Budget details page**: Updates frequently but may show a lower amount than a recent alert email when viewed shortly after.
  + **`system.billing.usage`**: Updates every few hours. Querying system tables shortly after receiving an alert may return a lower spend figure than the budget details page or alert emails.
