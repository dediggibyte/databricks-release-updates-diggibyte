Consumer access is a workspace entitlement that gives users access to workspace-level Genie One. When users with consumer access sign in, they are directed to Genie One instead of the standard Databricks workspace, where they can discover and interact with dashboards, Genie Agents, and Databricks Apps shared with them. Account-level Genie One is available to all Databricks account users and does not require this entitlement. See [Account-level Genie One](/aws/en/genie-one/#account-level-genie).

This page explains how workspace admins can grant consumer access, outlines the capabilities and restrictions for users with this entitlement, and describes relevant data governance controls.

## Consumer access capabilities

Consumer access is a [workspace entitlement](/aws/en/security/auth/entitlements) that workspace admins can assign to individual users or user groups. It adds business users to the workspace under a unified permissions model, but restricts their permissions so they can't create workspace objects. Because entitlements are additive, users benefit from the consumer experience only if consumer access is their sole entitlement within the workspace. Assigning additional workspace entitlements overrides the simplified consumer experience. After you migrate a workspace to the new system group behavior, you select each principal's entitlements when you add them, so you can add consumer-only users without granting authoring permissions. See [Migrate workspace entitlement control](/aws/en/security/auth/system-group-entitlements-migration).

Users with only the consumer access entitlement receive:

* Access to Genie One, a simplified workspace interface focused on consuming dashboards, Genie Agents, and Databricks Apps shared with them.
* Access to Unity Gateway services shared with them. Using the Unity Gateway CLI (`ug`) or the REST API, consumer access users can:
  + List model services and query Databricks-hosted foundation models.
  + List model provider services and query registered external providers.
  + List MCP services and call the MCP tools shared with them. The `system.ai.web_search` and `system.ai.sandbox` built-in MCP services aren't available to consumer access users.
  + List and download shared skills.
  + Read and apply an admin-published coding agent configuration.
  + Send client-side traces from their coding agent to the unified trace table, if an admin turns on tracing in the coding agent configuration. See [Enable client-side tracing](/aws/en/ai-gateway/coding-agent-observability#client-side-tracing).
  + Check their own spend against their coding agent budget with `ug usage`.
* Membership in the workspace’s users system group, displayed as the `users` group in the UI.
* Eligibility to be granted access to SQL warehouses for use with third-party BI tools, such as Power BI and Tableau. However, consumer access users cannot view SQL warehouses or **Query History**, even if permissions on compute and data have been granted.

Users with only consumer access cannot create new objects in the workspace.

important

Until your workspace migrates to the new entitlement behavior, users with consumer access also inherit all entitlements granted to the `users` system group. If that group grants elevated privileges such as workspace access or Databricks SQL access, consumer users receive those privileges too. When you migrate, Databricks automatically moves those entitlements to a new group and you select each principal's entitlements individually going forward. This change is enforced for all workspaces on September 14, 2026. See [Migrate workspace entitlement control](/aws/en/security/auth/system-group-entitlements-migration).

To grant consumer access to an individual user, assign the **consumer access** entitlement in workspace settings. See [Manage entitlements](/aws/en/security/auth/entitlements). To add consumer access users at scale, sync groups from your identity provider using automatic identity management. See [Automatic identity management](/aws/en/admin/users-groups/automatic-identity-management/).

## Data governance

Consumer access users are members of the workspace and work within the unified data access controls you've set up using Unity Catalog. They can view and run dashboards, Genie Agents, and Databricks Apps shared with them directly or shared with a group they belong to. If the sharing user has selected the option to run queries using the viewer's credentials, the viewer's own Unity Catalog privileges apply, and they see only the data they're authorized to access. They can also be assigned permissions to use Unity Catalog-governed data in third-party BI tools.

Every Genie One interaction respects Unity Catalog permissions. When users connect external knowledge sources such as Google Drive or SharePoint, Genie One honors those sources' permissions as well.
