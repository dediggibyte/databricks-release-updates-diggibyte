Beta

External access to views through the Iceberg REST catalog is in [Beta](/aws/en/release-notes/release-types). Accessing views through the Unity REST API is generally available.

External engines can query Unity Catalog views using the following APIs:

* [Unity REST API](/aws/en/external-access/unity-rest) for views over Delta Lake tables.
* [Iceberg REST catalog](/aws/en/external-access/iceberg) for views over Iceberg-compatible tables.

The external engine runs the view's SQL and reads the underlying tables. The reader must have access to the view and every referenced view or table.

## Requirements

* Enable **External data access** for the metastore. See [Enable external data access to Unity Catalog](/aws/en/external-access/admin).
* Grant `USE CATALOG` and `USE SCHEMA` on the parent catalogs and schemas, `SELECT` on the view and every referenced view or table, and `EXTERNAL USE SCHEMA` on the schemas containing those tables.
* Authenticate with a Databricks personal access token or OAuth token.
* Use view SQL that is compatible with the external engine.

## Query views from Apache Spark

Minimum versions for the Spark examples:

* Apache Spark 4.0.
* For Delta views: Unity Catalog Spark connector 0.6.0 and Delta Lake 4.3.0.
* For Iceberg views: Apache Iceberg 1.10.0.

Use Unity Catalog catalog names as Spark catalog names, including for catalogs referenced by the view.

### Views over Delta tables

The following example uses the Unity REST API on AWS. Replace:

* `<catalog>` with the Unity Catalog catalog containing the view.
* `<workspace-hostname>` with your Databricks workspace hostname.
* `<token>` with your access token.

Properties

```
spark.jars.packages io.unitycatalog:unitycatalog-spark_4.0_2.13:0.6.0,io.delta:delta-spark_4.0_2.13:4.3.0,org.apache.hadoop:hadoop-aws:3.4.1  
spark.sql.extensions io.delta.sql.DeltaSparkSessionExtension  
spark.sql.catalog.spark_catalog org.apache.spark.sql.delta.catalog.DeltaCatalog  
spark.sql.catalog.<catalog> io.unitycatalog.spark.UCSingleCatalog  
spark.sql.catalog.<catalog>.uri https://<workspace-hostname>  
spark.sql.catalog.<catalog>.token <token>  
spark.sql.defaultCatalog <catalog>  
spark.hadoop.fs.s3.impl org.apache.hadoop.fs.s3a.S3AFileSystem  
spark.hadoop.fs.s3a.impl org.apache.hadoop.fs.s3a.S3AFileSystem
```

To query the view, replace `<catalog>`, `<schema>`, and `<view>` with your catalog, schema, and view names, then run the following SQL in Spark:

SQL

```
SELECT * FROM <catalog>.<schema>.<view>;
```

### Views over Iceberg tables

The following example uses the Iceberg REST catalog on AWS. Replace:

* `<catalog>` with the Unity Catalog catalog containing the view.
* `<workspace-hostname>` with your Databricks workspace hostname.
* `<token>` with your access token.

Properties

```
spark.jars.packages org.apache.iceberg:iceberg-spark-runtime-4.0_2.13:1.10.0,org.apache.iceberg:iceberg-aws-bundle:1.10.0  
spark.sql.extensions org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions  
spark.sql.catalog.<catalog> org.apache.iceberg.spark.SparkCatalog  
spark.sql.catalog.<catalog>.type rest  
spark.sql.catalog.<catalog>.uri https://<workspace-hostname>/api/2.1/unity-catalog/iceberg-rest  
spark.sql.catalog.<catalog>.warehouse <catalog>  
spark.sql.catalog.<catalog>.token <token>  
spark.sql.catalog.<catalog>.io-impl org.apache.iceberg.aws.s3.S3FileIO  
spark.sql.catalog.<catalog>.header.X-Iceberg-Access-Delegation vended-credentials  
spark.sql.defaultCatalog <catalog>
```

To query the view, replace `<catalog>`, `<schema>`, and `<view>` with your catalog, schema, and view names, then run the following SQL in Spark:

SQL

```
SELECT * FROM <catalog>.<schema>.<view>;
```

## Limitations

* Creating and altering views from external compute is unsupported.
* The external engine must support view definitions in the Spark SQL dialect. Queries that reference the view use the external engine's SQL dialect.

For Iceberg REST catalog access:

* Views with fine-grained access control policies, custom resolution paths, or user-defined functions are unsupported.
* Historical view versions are unsupported.
* Spark uses the reader's SQL settings. Results or errors can differ from Databricks Runtime.
