Lakeflow Designer includes built-in operators for common data preparation and transformation tasks. Open the **Operators** pane on the left to browse operators by category, or use **Search for an operator...** at the top of the pane. Operator search suggests operators based on your intent. For example, typing `average by month` returns the **Aggregate** operator. See [Find operators with AI search](/aws/en/designer/genie-code#operator-search). To configure an operator after you add it to the canvas, double-click it, or hover over it and click  (**Edit operator**), to open the configuration pane.

Each operator displays an AI-generated description of what it does. The description also acts as an editor for the operator: editing the description reconfigures the operator to match your description.

When no built-in operator fits your task, you can [create your own operator](#create-your-own).

## Input and output

### Source

Imports data into Designer from a Unity Catalog table or other supported source. To select a source, search for a table or file by name, or browse by catalog and schema. You can also create a new table from this pane.

After you select a table, the pane shows the table's name, owner, and last updated time. Click **Select a new data source** to change the source. Changing the source invalidates the output cache for all downstream operators.

You can also use a Unity Catalog metric view as a source. When you select a metric view, select the dimensions and measures to include, and Designer generates the aggregated query for you.

For the full range of data ingestion options, including targeting an entire Unity Catalog volume or folder, see [Ingest data into Lakeflow Designer](/aws/en/designer/ingest-data).

### Output

Exports data out of Designer. The Output operator can write results to a Unity Catalog table, publish them as a materialized view, or write them to a file in a Unity Catalog volume, Google Drive, or SharePoint. In **Output type**, select **Table**, **Materialized view**, or **File**. For a file output, select where to write it in **Destination**.

| Output type | Description |
| --- | --- |
| Table | Writes the results to a managed Unity Catalog table. Set a **Table name** and an **Output location** (catalog and schema), then select a **Write mode**. |
| Materialized view | Publishes the results as a materialized view in Unity Catalog that refreshes when the visual data prep runs. |
| File | Writes the results as CSV, Excel, or JSON. Select the **Destination**, **File type**, and **File name**. |

Click **Run** to run the visual data prep and write the results. For a table output, if the table doesn't exist, the operator creates it. Scheduled runs write to the destination using the same write mode.

After an **Output** operator writes a Unity Catalog table, materialized view, or volume file, connect its outgoing port to continue the workflow. For tables, materialized views, and plain single-file outputs, the outgoing port reads directly from the persistent asset that the **Output** operator just wrote. For split outputs, Excel range writes, and files without headers, the outgoing port passes through the input rows.

For file outputs in a Unity Catalog volume, expand **Advanced** to configure the following options:

* **Split by distinct values**: Select a column to write one file for each distinct value. For Excel output, you can instead write each value to a separate worksheet in one workbook. A run can create up to 50 files or worksheets.
* **Sheet name**: For Excel output, set the target worksheet.
* **Include header row**: Include column names in CSV or Excel output.
* **Cell range**: For Excel output in **Overwrite** mode, set the starting cell and an optional ending cell. Designer preserves formatting outside the range and fails the run if the data doesn't fit a fixed range. You can't combine a cell range with **Split by distinct values**.

warning

When **Overwrite** mode splits output into files, Designer removes existing files that match the generated name pattern. This can include manually created files with the same pattern in the volume folder.

To write a file to Google Drive or SharePoint:

1. Set **Output type** to **File** and **Destination** to **Google Drive** or **Microsoft 365** for SharePoint.
2. Enable the corresponding [Genie Code connector](/aws/en/genie-code/mcp#connectors) and select **Connect** if prompted. Sign in with an account that has write access to the destination folder.
3. In **Folder URL**, paste the link to the Google Drive or SharePoint folder. In SharePoint, get the link with **Copy link**.
4. Enter a **File name**, choose a **File type**, and click **Run**.

Each run creates the file or replaces the complete contents of the existing file with the same name, including every Excel worksheet. The export must fit in one file of up to 2.75 MiB. Previews show the input data without writing the file. Scheduled runs use the run-as user's account and connector credentials.

### Guardrails

Validates incoming data against an ordered list of checks and separates rows that pass from rows that fail.

| Field | Description |
| --- | --- |
| Checks | Add **Required columns**, **Row count**, **Not null**, **Unique**, **Accepted values**, **Disallowed values**, **Value range**, **Regex match**, or **Expression** checks. |
| When a check fails | Choose one of three options to control output and downstream behavior. |

←✕

| Field | Description |
| --- | --- |
| Checks | Add **Required columns**, **Row count**, **Not null**, **Unique**, **Accepted values**, **Disallowed values**, **Value range**, **Regex match**, or **Expression** checks. |
| When a check fails | Choose one of three options to control output and downstream behavior. |

* **Warn and continue with passed rows**:
  + Downstream execution continues.
  + Rows that pass every enabled check are sent to **Passed**.
  + Rows that fail at least one enabled check are sent to **Failed**.
  + **Errors** contains one row for each failed check, including its type, severity, and message.
* **Warn and block passed output**:
  + If a check fails, downstream execution continues, but **Passed** contains no rows.
  + **Failed** still contains the failed rows, and **Errors** still contains the failure details.
  + Use this option to prevent downstream processing of passing rows while allowing downstream handling of **Failed** and **Errors**.
* **Fail the workflow**:
  + If a check fails, execution stops before downstream operators run.
  + They do not receive the **Passed**, **Failed**, or **Errors** outputs.
  + In a scheduled job, the run is marked as failed, which can trigger configured failure handling such as [job notifications](/aws/en/jobs/notifications).

When you preview the Guardrails operator itself, you can still inspect all three outputs in **Fail the workflow** mode.

To persist rows from an output in either warning mode, connect it to an Output operator.
