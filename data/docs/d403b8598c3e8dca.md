The Databricks Excel Add-in connects your Databricks workspace to Microsoft Excel, bringing governed Lakehouse data directly into your spreadsheets to help you move from data to decisions faster.

This page describes how to use the Databricks Excel Add-in to import and analyze data from Databricks in Excel. You can browse and import Databricks tables through an intuitive interface where no SQL knowledge is required. While the add-in offers the flexibility to execute custom SQL queries, it is optional.

## Prerequisites

* Before you use the Excel Add-in, verify that you have it [set up](/aws/en/integrations/excel-setup).
* You have [Databricks SQL access](/aws/en/security/auth/entitlements) and at least CAN USE permission on a [SQL warehouse](/aws/en/compute/sql-warehouse/).

## Select a SQL warehouse

Choose which SQL warehouse to use:

1. In the upper-right of the Databricks Add-in pane in Excel, click the drop-down menu.
2. Select which SQL warehouse you want to use.

## Import data from Databricks

Import data from Databricks in Excel by selecting a table, writing a SQL query, or importing a pivot table.

note

You can import Unity Catalog metric views using pivot tables, SQL queries, and custom functions.

### Create pivot tables

To create a pivot table from Unity Catalog tables and views in Excel:

1. In the Databricks Excel Add-in pane, under the **New import** tab, select **Select data** as the **Import method**.
2. Under **Catalog**, select the table you want to create a pivot table from and click **Select**.
3. Select the **Pivot Data** checkbox.
4. Configure **Row**, **Column**, and **Value** by dragging each field to the correct area.
5. (Optional) Add a **Filter**. For more information about filters, see [Filter imported data](#filters).
6. (Optional) To see a sample of the import, click **Preview**.
7. (Optional) Set a row limit for your import.
8. Import your results. Choose one of the following:

   * Click **Save and import** to save the query for reuse in the Excel workbook and import the results.
   * Click the down arrow, then click **Import results** to import the results without saving the query. Use this option when you want to continue editing an import.

   note

   Pivot tables can only be imported to a new sheet.

When working with Unity Catalog metrics in pivot tables, you might see `Sum(measure)` displayed in the results. This is expected behavior and no additional aggregation occurs. Excel requires that values have an aggregation function, but because the data contains unique values, no aggregation occurs.

### Select tables

Data is imported as an Excel table object. You can move the table or rename the sheet, and the Excel Add-in refreshes data in the new location.

To import data from a Databricks table, do the following:

1. In the Databricks Excel Add-in pane, under the **New import** tab, select **Select data** as the **Import method**.
2. Choose a table to import from the Catalog explorer. You can filter the catalog by owner, certification status, and other properties using  filter.
3. Click **Select**.
4. Under **Columns**, click the down arrow and deselect the columns you don't want to import, or leave all columns selected to import the entire table.
5. (Optional) Add a **Filter**. For more information about filters, see [Filter imported data](#filters).
6. (Optional) To see a sample of the import, click **Preview**.
7. (Optional) Set a row limit to restrict the number of rows imported.
8. (Optional) To identify your imported data, enter an **Import name**.
9. Under **Output Destination**, choose to import the data to a new sheet or the current sheet. If you import to the current sheet, data starts at the cell reference you enter (by default A1).
10. Import your results. Choose one of the following:
    * Click **Save and import** to save the query for reuse in the Excel workbook and import the results.
    * Click the down arrow, then click **Import results** to import the results without saving the query. Use this option when you want to continue editing an import.

### Write SQL queries

The **Write SQL** import method supports SQL functions and stored procedures.

To run custom SQL queries against your Databricks workspace, do the following:

1. In the Databricks Excel Add-in pane, under the **New import** tab, select **Write SQL** as the **Import method**.
2. Enter a name for your query to identify it later.
3. Write a new query or use an existing query from your Databricks workspace.

   * Write your SQL query in the editor. You can query any table in Unity Catalog that you have permissions to access.

     + Click  Catalog explorer to view your schemas and tables.
   * To use a query from your Databricks workspace or an existing query in Excel, click  the folder. If you use an existing query from your Databricks workspace, edits made in Excel are not reflected on Databricks.

     note

     Queries must be explicitly saved in Databricks using the **Save** button in the top-right corner of the query editor before they appear in Excel.
4. (Optional) To add query parameters, click **+Add** next to **Parameters**. Click the parameter and enter the **Parameter Name** and **Parameter Value**.

   * For the parameter value, you can either enter a specific value or click the box and arrow button to specify a cell reference. Select a cell or range of cells and click the arrow to automatically fill the parameter value.
5. Under **Output Destination**, choose to import the data to a new sheet or the current sheet. If you import to the current sheet, data starts at the cell reference you enter (by default A1).
6. To preview your query results, click **Run**.
7. Import your results. Choose one of the following:

   * Click **Save and import** to save the query for reuse in the Excel workbook and import the results.
   * Click the down arrow, then click **Import results** to import the results without saving the query. Use this option when you want to continue editing an import.

You can also use custom functions to add query parameters. See [Write SQL](#func-write-sql).

### Filter imported data

When you import data by selecting a table or creating a pivot table, you can apply filters to narrow the results.

String filters are case-insensitive and cascading. When you apply more than one filter, the available values for each filter depend on the selections in the filters before it. For example, if you filter by country and then add a filter on city, the city filter offers only cities within the selected country.

To set filters, click **+** next to **Filters**, select the column that you want to apply a filter to, and then enter your filter condition. For filters that require a value, you can do one of the following:

* Enter the value.
* To generate a list of up to 5,000 distinct filter values you can use:
  1. Click **Values**, then **Get filter values**.
  2. Click the down arrow and select one or more values from the list.
* To use a cell reference:
  1. Click **Cells**.
  2. Select a cell or range of cells.
  3. Click the cursor .

The following table describes each available filter and its expected input.

| Filter | Expected input | Description |
| --- | --- | --- |
| `IS NULL` | None | Finds rows where the column value is null. |
| `IS NOT NULL` | None | Finds rows where the column value is not null. |
| `EQUALS` | One number or text string | Finds rows where the column value exactly matches the specified value. |
| `NOT EQUALS` | One number or text string | Finds rows where the column value does not match the specified value. |
| `ILIKE` | One pattern using `%` (any characters) and `_` (single character) as wildcards.  `%Smith` matches values like "smith", "Smith", or "SMITH".  `_ob` matches "Bob", "rob", or "Rob". | Finds rows where the column value matches the pattern. Case-insensitive. |

| `ENDS WITH` | One text string | Finds rows where the column value ends with the specified text. |

## Use Databricks custom functions in Excel

The Excel Add-in provides custom functions that you can use in Excel formulas to import data from Databricks.

### Select a table

The `DATABRICKS.Table` function imports data from a Unity Catalog table.

**Syntax:**

Text

```
=DATABRICKS.Table(catalog_name.schema_name.table_name, [column1, ...], [limit])
```

**Parameters:**

* `catalog_name.schema_name.table_name` (required): The fully qualified table name.
* `columns` (optional): An array of column names to import. Omit this parameter to import all columns.
* `limit` (optional): The maximum number of rows to import. Omit this parameter to import all rows, up to the 10 MB limit.

**Example:**

Text

```
=DATABRICKS.Table("main.default.customers", {"customer_id", "customer_name"}, 100)
```

This formula imports the `customer_id` and `customer_name` columns from the `main.default.customers` table, limited to 100 rows.

### Write SQL

The `DATABRICKS.SQL` function runs a SQL query that uses query parameters and returns the results.

**Syntax:**

Specify parameters using values.

Text

```
=DATABRICKS.SQL("query_text", {parameter1_name, parameter1_value; ...})
```

Specify parameters using a cell range. Define the name and value parameters in cells that are in the same row.

Text

```
=DATABRICKS.SQL("query_text", {param_name_cell: param_value_cell; ...})
```

**Parameters:**

* `query_text` (required): The SQL query to run.
* `parameters` (required): A mapping of parameter values to substitute into the query.

**Example:**

Text

```
=DATABRICKS.SQL("SELECT * FROM samples.bakehouse.sales_suppliers WHERE longitude > :long_param AND latitude > :lat_param LIMIT 10", {"long_param",20; "lat_param",10})  
  
=DATABRICKS.SQL("SELECT * FROM samples.bakehouse.sales_suppliers WHERE city = :city", M4:N4)
```

This formula runs a query that filters sales data by `longitude` and `latitude`, using the provided parameter values.

## Manage queries

Manage your existing imports from the Imports page.

### Edit an existing import

To edit an existing import:

1. In the Databricks Add-in pane in Excel, click the **Imports** tab.
2. Find the import you want to edit.
3. Click the three-dot menu next to the import.
4. Click **Edit** to edit your import.

### Refresh data

The Excel Add-in does not refresh data automatically. How you refresh data depends on how you imported it. Data imported using an import method (select a table, write a SQL query, or create a pivot table) refreshes from the **Imports** tab. Data imported using a custom function must be recalculated.

Update imports with the latest values from Databricks. The Add-in runs the original query or table selection again and updates your worksheet with fresh data:

* To refresh a single import:
  1. In the Databricks Add-in pane in Excel, click the **Imports** tab.
  2. Click  refresh next to the import you want to refresh.
* To refresh all imports:
  1. Click **Refresh All** in the Databricks Add-in pane.

important

When refreshing data, the Excel Add-in clears all existing data in the specified table and reloads the newest data from Databricks. Any custom columns you added to the table are deleted during the refresh process.

Data imported from custom functions, such as `DATABRICKS.Table` and `DATABRICKS.SQL`, does not refresh when you reopen a workbook. To refresh data imported from custom functions, sign in to the Databricks Add-in, then either recalculate the workbook or change a value the custom function references.

## Sharing implications

When you share an Excel workbook that contains Databricks data, consider the following data access and security implications:

### Visibility to imported data

When a recipient refreshes an import, the Add-in uses the recipient's Unity Catalog permissions. If they do not have access to the underlying data, the refresh fails.

For workbooks where data privacy is a concern, you can use the following workaround:

1. Create a workbook with all necessary formulas and imports.
2. Delete the imported data from the sheet.
3. Share the workbook with the recipient.
4. Have the recipient refresh the data.

The recipient only sees data they have access to based on their Unity Catalog permissions.

### Access to workspaces and data assets

* Users without access to the Unity Catalog objects referenced in the workbook can't refresh the data. To refresh data, users must have read permissions on the underlying tables and views in Unity Catalog.
* Users must have access to the underlying table in Databricks to edit existing imports.
