This page has examples for managing files in Unity Catalog [volumes](/aws/en/volumes/) for various user interfaces, tools, libraries, and languages.

note

Available in Beta, use the `FILE` type to reference files in volumes as values in a table and apply table access controls to them. See [FILE type and unstructured data](/aws/en/unstructured/file).

Databricks recommends using volumes for managing all access to non-tabular data in cloud object storage and for storing workload support files. Examples include the following:

* Data files for ingestion, such as CSV, JSON, and Parquet
* Text, image, and audio files for data science, ML, and AI workloads
* CSV or JSON artifacts written by Databricks for integration with external systems
* Libraries, init scripts, and build artifacts

Volumes provide Portable Operating System Interface (POSIX)-style paths that work with Filesystem in Userspace (FUSE)-dependent tools and frameworks. This makes them ideal for machine learning frameworks and open source Python modules that require POSIX-style access. For detailed information about URI schemes, POSIX paths, and how they relate to volumes, see [Do I need to provide a URI scheme to access data?](/aws/en/files/#paths).

## Use Catalog Explorer

Catalog Explorer has options for common file management tasks for files stored with Unity Catalog volumes.

To interact with files in a volume, do the following:

1. In your Databricks workspace, click  **Catalog**.
2. Search or browse for the volume that you want to work with and select it.

For details on creating and managing volumes, see [Create and manage Unity Catalog volumes](/aws/en/volumes/utility-commands).

### Upload files to a volume

You can upload files of any format—structured, semi-structured, or unstructured—to a volume. Volumes support files up to the maximum size supported by the underlying cloud storage. However, when you upload files to a volume through the Databricks UI, there's a 5 GB file size limit. To upload files larger than 5 GB, use the Databricks SDK for Python. For details, see [Manage files in Unity Catalog volumes](/aws/en/dev-tools/sdk-python#manage-files-in-unity-catalog-volumes).

#### Requirements

Before you upload to a volume, make sure you have the following:

* A workspace with Unity Catalog enabled
* `WRITE VOLUME` on the target volume
* `USE SCHEMA` on the parent schema
* `USE CATALOG` on the parent catalog

For details, see [Unity Catalog privileges reference](/aws/en/data-governance/unity-catalog/access-control/privileges-reference).

#### Upload steps

1. In the sidebar, click **New**, then **Add or upload data**.
2. Click **Upload files to a volume**.
3. Under **Files**, click **browse** or drag and drop files into the drop zone.
4. Under **Destination volume**, select a volume or directory, or paste a volume path.

If no volume exists in the target schema, you can create one by clicking **Create volume**. Within the volume, you can create a new directory.

note

To upload your own files without first creating a catalog, schema, and volume, you can select My Files, a per-user volume, as the destination. My Files is in [Beta](/aws/en/release-notes/release-types). See [Store files in My Files](/aws/en/volumes/my-files).

You can also access the upload UI in the following ways:

* In Catalog Explorer: **Add data** > **Upload files to a volume**
* From a notebook: **File** > **Upload files to volume**

#### Next steps

After you upload to a volume, you can do the following:

* Create a Unity Catalog managed table from the files. See [Create a table from data in a volume](#create-table).
* Use the files in ML and data science workloads
* Configure cluster libraries, notebook-scoped libraries, or job dependencies using the uploaded files
* Ingest data for engineering pipelines using [Auto Loader](/aws/en/ingestion/cloud-object-storage/auto-loader/patterns) or [COPY INTO](/aws/en/ingestion/cloud-object-storage/copy-into/unity-catalog)
* Process files with [AI functions](/aws/en/large-language-models/ai-functions) such as [`ai_parse_document`](/aws/en/sql/language-manual/functions/ai_parse_document)
* Set up [file arrival triggers](/aws/en/jobs/file-arrival-triggers) in jobs

* Upload documents for use with [Knowledge Assistant](/aws/en/agents/agent-bricks/knowledge-assistant)

### Edit files in a volume

You can open a text file stored in a volume in the Databricks file editor and edit it in place, without downloading the file and uploading it again. The editor saves your changes to the volume automatically.

To open a file in the editor, you need these privileges:

* `READ VOLUME` on the volume
* `USE SCHEMA` on the parent schema
* `USE CATALOG` on the parent catalog
* `WRITE VOLUME` on the volume to save changes. For details, see [Unity Catalog privileges reference](/aws/en/data-governance/unity-catalog/access-control/privileges-reference).

To edit a file in a volume:

1. In Catalog Explorer, browse to the volume that contains the file.
2. Click the  kebab menu next to the file name, and then click **Open in Editor**.

   You can also click the file name to open its preview, and then click the  **Open in Editor** icon.
3. Edit the file. The editor saves your changes to the volume automatically.

You can also open a volume file from a notebook or the SQL editor. In the [schema browser](/aws/en/notebooks/notebook-editor#browse-data), hover over the file, click the  kebab menu, and then click **Open file**.

If the file changes outside the editor while you have it open, the editor shows a **Conflict detected** dialog. Click **Yes, I would like to fetch the latest changes** to load the latest version of the file, or click **No, overwrite contents** to save your version over it.

In the editor, you can use [Genie Code](/aws/en/notebooks/code-assistant) to read and edit the file. Genie Code can edit only the file that is open in the editor, and only if you have `WRITE VOLUME` on the volume.

#### Supported file types

The editor opens files with these extensions:

* **Text files**: txt, log, md
* **Code files**: py, scala, sql, r, sh
* **Semi-structured data files**: json, ndjson, jsonl, csv, tsv, tab
* **Configuration files**: yaml, yml, toml, ini, conf, properties, env

Files named `stdout` or `stderr` also open in the editor.

#### Limitations

The editor has these limitations:

* If a file is larger than 10 MB, you can't open it in the editor. To edit the file, download it, edit it locally, and upload it again.
* If a file has an extension that isn't in the preceding list, such as an image, PDF, or Parquet file, you can't open it in the editor. You can still preview supported formats such as images, PDFs, and Parquet files. See  [Preview files in volumes](/aws/en/discover/files#preview).

* The file editor isn't available in AWS GovCloud regions.

### Download files from a volume

To download files from a volume, do the following:

1. Select one or more files.
2. Click **Download** to download these files.

### Delete files from a volume

To delete files from a volume, do the following:

1. Select one or more files.
2. Click **Delete**.
3. Click **Delete** to confirm in the dialog that appears.

### Create a blank directory

To create a new directory in a volume, do the following:

1. On the volume overview tab, click **Create directory**.
2. Enter a directory name.
3. Click **Create**.

### Download a directory

To download a directory in a volume, do the following:

1. Click the  kebab menu to the right of the directory.
2. Click **Download directory**.

The directory is downloaded as a ZIP file.

### Delete directories from a volume

To delete directories from a volume, do the following:

1. Select one or more directories.
2. Click **Delete**.
3. Click **Delete** to confirm in the dialog that appears.

### UI file management tasks for volumes

Click the  kebab menu next to a file name to perform the following actions:

* Open in Editor (supported text files only). See [Edit files in a volume](#edit-files).
* Copy path
* Download file
* Delete file
* Create table

### Create a table from data in a volume

Databricks provides a UI to create a Unity Catalog managed table from a file, files, or directory of files stored in a Unity Catalog volume.

You must have `CREATE TABLE` permissions in the target schema and have access to a running SQL warehouse.

1. Select one or more files or a directory. Files should have the same data layout.
2. Click **Create table**. The **Create table from volumes** dialog appears.
3. Use the provided dialog to review a preview of the data and complete the following configurations:

   * Choose to **Create new table** or **Overwrite existing table**
   * Select the target **Catalog** and **Schema**.
   * Specify the **Table name**.
   * (Optional) Override default column names and types, or choose to exclude columns.

   note

   Click **Advanced attributes** to view additional options.
4. Click **Create table** to create the table with the specified attributes. Upon completion, Catalog Explorer displays the table details.

## Programmatically work with files in volumes

Read and write files in volumes from all supported languages and workspace editors using the following format:

`/Volumes/catalog_name/schema_name/volume_name/path/to/files`

You interact with files in volumes in the same way that you interact with files in any cloud object storage location. That means that if you currently manage code that uses cloud URIs, DBFS mount paths, or DBFS root paths to interact with data or files, you can update your code to use volumes instead.

note

Volumes are only used for non-tabular data. Databricks recommends registering tabular data using Unity Catalog tables and then reading and writing data using table names.

### Read and write data in volumes

Use Apache Spark, pandas, Spark SQL, and other OSS libraries to read and write data files in volumes.

The following examples demonstrate reading a CSV file stored in a volume:

* Python
* Pandas
* SQL

Python

```
df = spark.read.format("csv").load("/Volumes/catalog_name/schema_name/volume_name/data.csv")

display(df)
```

Python

```
import pandas as pd

df = pd.read_csv('/Volumes/catalog_name/schema_name/volume_name/data.csv')

display(df)
```

SQL

```
SELECT * FROM csv.`/Volumes/catalog_name/schema_name/volume_name/data.csv`
```

### Utility commands for files in volumes

Databricks provides the following tools for managing files in volumes:

* The `dbutils.fs` submodule in Databricks Utilities. See [File system utility (dbutils.fs)](/aws/en/dev-tools/databricks-utils#dbutils-fs).
* The `%fs` magic, which is an alias for `dbutils.fs`.
* The `%sh` magic, which allows bash command against volumes.

For an example of using these tools to download files from the internet, unzip files, and move files from ephemeral block storage to volumes, see [Download data from the internet](/aws/en/volumes/download-internet-files).

You can also use OSS packages for file utility commands, such as the Python `os` module, as shown in the following example:

Python

```
import os

os.mkdir('/Volumes/catalog_name/schema_name/volume_name/directory_name')
```

### DataFrame checkpoints in volumes

You can use Unity Catalog volume paths to store [DataFrame checkpoints](https://spark.apache.org/docs/latest/api/python/reference/pyspark.sql/api/pyspark.sql.DataFrame.checkpoint.html). DataFrame checkpoints truncate the execution plan of a DataFrame and save the contents to storage. This can improve performance for iterative algorithms and complex query plans by preventing excessively long lineages when reusing DataFrames.
