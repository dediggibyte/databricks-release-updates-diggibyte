Create a Jira connection in Catalog Explorer to store authentication credentials for Lakeflow Connect ingestion. Any user with the `USE CONNECTION` privilege on the connection can then create Jira ingestion pipelines without needing direct access to the credentials.

Alternatively, admin users can create a connection and a pipeline at the same time in the data ingestion UI. See [Create an ingestion pipeline](/aws/en/ingestion/lakeflow-connect/jira-pipeline).

For privilege requirements, see [Connect to managed ingestion sources](/aws/en/connect/managed-ingestion).

## Prerequisites

Complete the [source setup](/aws/en/ingestion/lakeflow-connect/jira-source-setup). Use the authentication details you obtain to create the connection.

## Create a connection

* U2M OAuth
* M2M OAuth

1. In the Databricks workspace, click  **Catalog > Create > Create a connection**.
2. On the **Connection basics** page of the **Set up connection** wizard, specify a unique **Connection name**.
3. In the **Connection type** drop-down menu, select **Jira**.
4. In the **Auth type** drop-down menu, select **OAuth User to Machine**.
5. (Optional) Add a comment.
6. Click **Next**.
7. On the **Authentication** page, enter the following:
   * **Host**: The domain for the Jira data source, including `http/https`.
   * (Optional) **Port**: The port for an on-premises Jira instance. The default is 443.
   * **Client secret**: The client secret from the source setup.
   * **Client ID**: The client ID from the source setup.
   * (Optional) **On premise**: Select if the Jira instance is on-premises.
   * (Optional) **Jira deployment path**: The on-premises deployment path (for example, if the URL is `http://<domain>:<port>/<path>`, the path is `<path>`).
8. Click **Sign in with Jira** and authorize the Databricks application.

1. Complete the [M2M source setup](/aws/en/ingestion/lakeflow-connect/jira-source-setup#jira-cloud-m2m): create an OAuth 2.0 credential for an Atlassian service account. M2M supports Jira Cloud only.
2. In the Databricks workspace, click  **Catalog > Create > Create a connection**.
3. On the **Connection basics** page of the **Set up connection** wizard, specify a unique **Connection name**.
4. In the **Connection type** drop-down menu, select **Jira**.
5. In the **Auth type** drop-down menu, select **OAuth Machine to Machine**.
6. (Optional) Add a comment.
7. Click **Next**.
8. On the **Authentication** page, enter the following:

   * **Host**: The URL of your Jira Cloud site, for example `https://company.atlassian.net`.
   * **Client ID**: The client ID of the service account credential.
   * **Client secret**: The client secret of the service account credential.
9. Click **Create connection**.

   Databricks requests an access token from Atlassian using the client credentials. No browser sign-in is required. The pipeline runs with the service account's permissions, and Databricks gets a new access token automatically when the current one expires.
