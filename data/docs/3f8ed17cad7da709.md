**Applies to:**  Databricks SQL  Databricks Runtime

Beta

This feature is in [Beta](/aws/en/release-notes/release-types). To use it, a workspace admin must turn on **Ai Enrich** from the **Previews** page. See [Manage Databricks previews](/aws/en/admin/workspace-settings/manage-previews).

The `ai_enrich()` function generates new columns for a row from a schema you define. Given input content and a target schema, the function calls an AI model to fill in each field. It can optionally ground the generated values in one or more [knowledge sources](#knowledge-source-configuration) like an [AI Search index](/aws/en/ai-search/ai-search), a live web search, or a search tool on an [external Model Context Protocol (MCP) server](#mcp-config), so the values reflect your own data or up-to-date information rather than the model's training data alone.

Use `ai_enrich` to add derived attributes to a table at scale. You can tag and categorize records, fill in missing metadata, or attach researched context to each row from a single SQL function call. By default, each generated field is returned with a short rationale that explains how the value was derived.

## Requirements

* Databricks Runtime 18.2 or above.
* If you are using Serverless compute, the serverless environment version must be set to 3 or above, as this enables features like `VARIANT`.
* To ground enrichment in an AI Search index, you need one or more [AI Search indexes](/aws/en/ai-search/ai-search) to use as knowledge sources.
* To ground enrichment in an external MCP server, you need an MCP [registered in Unity Gateway](/aws/en/ai-gateway/register-mcp-service), `EXECUTE` on it, and `USE CATALOG` and `USE SCHEMA` on its parent catalog and schema. See [MCP configuration](#mcp-config).
* The `ai_enrich` function is available using Databricks notebooks, SQL editor, jobs, or Lakeflow pipelines.

## Data security

Your document data is processed within the Databricks security perimeter. Databricks does not store the parameters that are passed into the AI function calls, but does retain metadata run details, such as the Databricks Runtime version used.

If you configure an `mcp` knowledge source, the search query that `ai_enrich` builds from each row is sent to the external provider, so treat row content that reaches it as data that leaves Databricks. See [MCP configuration](#mcp-config).

## Syntax

```
ai_enrich(content, schema [, knowledge_sources] [, options])
```

## Arguments

* `content`: A `STRING` or `VARIANT` expression. The row to enrich. `VARIANT` input, such as the output of another AI function like `ai_parse_document`, is serialized to a JSON string internally.
* `schema`: A `STRING` literal that defines the columns to generate. It uses the same grammar as [`ai_extract`](/aws/en/sql/language-manual/functions/ai_extract). The schema can be:

  + Simple schema: A JSON array of field names, which are generated as strings.

    JSON

    ```
    ["industry", "headquarters_country", "year_founded"]
    ```
  + Advanced schema: A JSON object with type information, descriptions, and nested structures.

    - Supports `string`, `integer`, `number`, `boolean`, and `enum` types. Performs type validation. Maximum of 500 enum values.
    - Supports nested objects using `"type": "object"` with `"properties"`.
    - Supports arrays of primitives or objects using `"type": "array"` with `"items"`.
    - Optional `"description"` field for each property to guide the generated value.

    JSON

    ```
    {

    "hq_address": {

    "type": "object",

    "description": "Registered headquarters address",

    "properties": {

    "city": { "type": "string" },

    "country": { "type": "string" }

    }

    },

    "founding_team": { "type": "array", "description": "Full names of the founders", "items": { "type": "string" } },

    "founding_year": { "type": "integer", "description": "Year the company was founded" }

    }
    ```
* `knowledge_sources`: An optional `VARIANT` or `STRING` expression containing a JSON array of knowledge source configurations used to ground the generated values. See [Knowledge source configuration](#knowledge-source-configuration).
* `options`: An optional `MAP<STRING, STRING>`. Supported keys:

  + `'version'`: The function version to use.
  + `'instructions'`: A `STRING` of up to 20,000 characters. Natural-language guidance that describes the enrichment task. Optional; the schema field names alone can drive the enrichment. For example, `'Infer attributes for each company from its public profile.'`
  + `'enableRationale'`: `'true'` (default) or `'false'`. When `'true'`, each generated field is returned as a `{rationale, value}` object, where `rationale` explains how the value was derived. Set to `'false'` to return `{value}` only.

## Knowledge source configuration

The `knowledge_sources` argument is a JSON array. Each element is a `{type, description, config}` envelope. The `type` field identifies how `ai_enrich` retrieves grounding context, and the `config` field contains the source-specific configuration.

| Key | Required | Description |
| --- | --- | --- |
| `type` | Yes | The knowledge source type. One of `vector_search` (an AI Search index), `web_search`, or `mcp` (an external MCP server). |
| `description` | No | A natural-language description of the source. |
| `config` | Yes | An object containing the source-specific configuration. See [AI Search index configuration](#ai-search-index-config) for `vector_search`, [Web search configuration](#web-search-config) for `web_search`, and [MCP configuration](#mcp-config) for `mcp`. |

### MCP configuration

An `mcp` source grounds each row with a search tool on an external MCP server, such as [You.com](https://marketplace.databricks.com/details/32d5b7b6-0fab-4bba-9c57-5de23dd58996/Youcom_Youcom-MCP-The-1-AI-Web-Search-API) or [Exa](https://exa.ai/docs/reference/exa-mcp). Use it to ground rows in a search provider you already have an account with. `ai_enrich` calls the tool through Unity Gateway as the identity that runs the query. Each `mcp` source adds up to five result URLs to `metadata.sources`.

Before you use an `mcp` source:

1. Register the server as an MCP. See [External MCP servers](/aws/en/ai-gateway/register-mcp-service). For a server listed in Databricks Marketplace, such as You.com, installing the listing creates the MCP for you. See [Get access to external MCP servers](/aws/en/marketplace/get-started-consumer#install-mcp).
2. Use a connection with a shared credential, such as the provider's API key as a bearer token. `ai_enrich` can't prompt for sign-in, so if the connection requires each user to sign in, the `mcp` source fails for users who haven't signed in.
3. Grant `EXECUTE` on the MCP, and `USE CATALOG` and `USE SCHEMA` on its parent catalog and schema, to the identity that runs the query: each user, or the run-as identity of a job or pipeline. See [Share an MCP](/aws/en/ai-gateway/govern-mcp-service#control-callers).

For an `mcp` source, `config` accepts the following keys:

| Key | Required | Description |
| --- | --- | --- |
| `mcp_service` | Yes | The full name of the MCP, `<catalog>.<schema>.<service>`. |
| `tool` | Yes | The search tool to call, for example `you-search` for You.com or `web_search_exa` for Exa. The tool must be one that the MCP exposes. |
| `query_argument` | No | The tool argument that receives the search query. Defaults to `query`. |
| `arguments` | No | A JSON object of extra tool arguments to send on every call. For example, Exa's `web_search_exa` tool lists `objective` as a required argument. |
| `max_query_chars` | No | The maximum length of the search query, in characters. Defaults to 400. Longer queries are truncated. |

For each row with non-empty content, `ai_enrich` builds a short search query from the row content followed by the requested fields. Each top-level field contributes its description, or its name if it has no description. The query is cut to `max_query_chars`, so for a long row the field text can be cut off. `ai_enrich` calls the tool of every `mcp` source one time with that query. Each call times out after 60 seconds. A call that times out or fails with a 429, 500, 502, 503, or 504 error is retried up to three times. Because retries can repeat a call, use a read-only search tool. Calls to the provider count against your provider account's pricing and rate limits.

If a call fails and no other knowledge source returns results, `error_message` is set and `response` is `null` for that row. For example, a call fails if the provider rejects the API key or the identity that runs the query lacks `EXECUTE` on the MCP. If another knowledge source returns results, the row is grounded in those results only and no error is reported. If the tool returns no results and no other knowledge source does either, the row is enriched from its content alone, without grounding.

If `mcp` knowledge sources aren't enabled for the workspace, every row with non-empty content returns `null` for `response` and the `error_message` `mcp knowledge source is not available: it is not enabled for this workspace.`, even when the call also configures other knowledge sources.

You can configure more than one `mcp` source in a single call. For an example, see  [Ground enrichment in an external MCP search provider](#mcp-example).
