Authorized support contacts can use the Get support form to open a Databricks support case without leaving the workspace. The form collects your issue details, fills in values it can infer, attaches diagnostic files for the affected resources, and suggests an AI-generated solution before you submit.

To open a case in other ways, or to manage cases after you submit them, see [Databricks Support](/aws/en/resources/support).

## Prerequisites

* Your organization has a Databricks Support contract, and your email address is registered as an authorized support contact. See [Requirements for Databricks support](/aws/en/resources/support#requirements-for-databricks-support).
* You're signed in to a workspace that belongs to the account covered by the contract.

note

The Get support form isn't available in Databricks on AWS GovCloud or AWS GovCloud DoD workspaces. Submit cases from the [Databricks GovCloud Help Center](https://help.databricks.us/s/) or by email to [help@databricks.us](mailto:help@databricks.us).

## Open the Get support form

Open the form in either of these ways:

* Click your user icon in the top bar of the workspace, then click **Get support**.
* In the Genie Code pane, click **Get Support** in the **Need additional help?** banner.

When you open the form from a Genie Code conversation, the form can fill in more fields from that conversation. See [What the form fills in automatically](#what-the-form-fills-in-automatically).

The form saves your entries for up to 30 days. If you close and reopen the form, it restores your entries, except for screenshots and attachments, which you must upload again. To start over, click **Clear all fields**.

## What the form fills in automatically

The form fills in fields it can infer that you haven't already entered. You can change any filled-in value before you submit.

| Information | Source |
| --- | --- |
| Workspace, environment, business impact, and preferred time zone | The current workspace and default values. |
| Product | The page you opened the form from. For example, opening the form from a job run page selects **Runs**. |
| Product, sub-feature, issue, and description | Your Genie Code conversation, when you open the form from Genie Code with no saved entries. The form fills in these fields only when it's confident in the match. |
| [Resource fields](#gather-diagnostics) | The form looks for resource URLs and IDs in this order: your description, the page you opened the form from, and your Genie Code conversation if you opened the form from Genie Code. It verifies that each resource exists before filling it in. |
| Databricks Runtime version | The selected cluster. The form selects **Not applicable** when the run or notebook doesn't use classic compute, such as serverless compute. |
| Diagnostic files | The resources you identify. |
| Genie Code chat history | When you open the form from Genie Code, the current conversation. When you open the form from the user menu, your Genie Code conversations in the workspace from the past four hours. For long conversations, the form includes only the most recent messages. |

To improve how the form fills in fields, include full resource URLs in your description, or open the form from the page of the affected resource, such as a job run or cluster.

## Complete the form

The form has four steps: describe the issue, gather diagnostics, review the suggested solution, and review and submit.

### Describe the issue

The **Describe issue** step has these fields:

| Field | Required | Description |
| --- | --- | --- |
| **Workspace** | Yes | The affected workspace. Defaults to the current workspace. |
| **Product** | Yes | The area of Databricks where the issue occurs. |
| **Sub-feature** | Yes, if available | The part of the product where the issue occurs. Required when the selected product has sub-features. |
| **Issue** | Yes | **Problem**, **Question**, **Feature request**, or **Other**. |
| **Issue frequency** | Yes | **One-time**, **Recurring**, **Intermittent**, or **Not sure / other**. |
| **Issue start date** and **Last worked correctly** | Yes | Approximate dates are acceptable. |
| **Description** | Yes | What happened, what you expected, and any error messages. Appears after you select a product and, if required, a sub-feature. Include resource URLs or IDs so the form can fill in the resource fields. See [Gather diagnostics](#gather-diagnostics). You can paste screenshots into this field. |
| **Business and operational impact** | Yes, if business impact is **High**, **Urgent**, or **Mission Critical** | How the issue affects your business, such as the consequence, its scope, and the teams, processes, customers, or use cases affected. Appears with **Description**. |
| **Environment** | No (auto-set) | **Proof of concept**, **Development**, or **Production** (default). |
| **Business impact** | No (auto-set) | **Low**, **Normal** (default), **High**, or **Urgent**. Accounts with Mission Critical support can also select **Mission Critical**. For time-sensitive issues, select **Urgent** or higher, and describe the effect in **Business and operational impact**. See [Escalate a support case](/aws/en/resources/support#escalate-a-support-case). |
| **Preferred timezone** | No (auto-set) | The time zone Databricks Support uses to schedule engagement. Defaults to your saved preference, or to your browser's time zone if you don't have a saved preference. |
| **Notify teammates** | No | Email addresses of colleagues to add to the case. Added colleagues receive an email notification for each new comment on the case. |

To complete the step:

1. Fill in the required fields, and change any auto-set values that don't match your issue.
2. If you want help with your own code, such as debugging an Apache Spark application or tuning job performance, select **I want to use Spark support hours**. This option draws on your account's Spark and AI assistance hours. Leave it cleared for issues with the Databricks platform itself.
3. Click **Next**.

| Job run | Run information, task outputs, and SQL queries run by the job. Requires the full job run URL. |
| Query | Query information |
| SQL warehouse | Warehouse configuration, events, recent statements, failed queries, and a failure summary |
| Unity Catalog securable | Object information, effective permissions, and a metastore summary. Requires the full dotted name, such as `my_catalog.my_schema.my_table`. |
| Serving endpoint | Endpoint events, build logs, and serving logs |

To complete the step:

1. Under **Resource and execution details**, identify the resources involved in the issue. The cluster, job run, SQL warehouse, and Databricks Runtime fields are searchable pickers that list matching resources in the workspace. If a resource doesn't apply, select **Not applicable** where available, such as for the Databricks Runtime version when the issue runs on serverless compute.
2. Review the files under **Auto-generated diagnostic artifacts**. To view a file, click it. To exclude a file from the case, click  next to it.
3. Optionally, under **Additional details**, describe how to reproduce the issue in **Repro details**, and upload screenshots and attachments. Each file can be up to 10 MB.
