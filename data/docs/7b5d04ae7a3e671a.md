This page describes how to run notebooks in clean rooms. Notebooks are the interface that collaborators use to run data analysis in collaboration.

To learn how to add a notebook to a clean room, see [Create clean rooms](/aws/en/clean-rooms/create-clean-room).

## Requirements

To manage and run a notebook in a clean room, you must:

| Managing a notebook | No unique requirements | **For the notebook's uploader:**   * If they are the designated runner, they must have `EXECUTE CLEAN ROOM TASK` or `MODIFY CLEAN ROOM` privileges. * If a collaborator is the designated runner, the uploader must have the `MODIFY CLEAN ROOM` privilege. | General management tasks for a notebook in the clean room. |
| Running a notebook | Every collaborator, except the uploader, must approve the notebook. A designated runner runs the notebook. | `EXECUTE CLEAN ROOM TASK` | If the runner of the notebook did not upload it, they must approve the notebook before it can be run. | Managing auto-approval rules | Auto-approvals can only be applied to notebooks authored by collaborators other than the runner. | Clean room owner or `MANAGE` privilege. | Controls the automatic approval of notebooks. |
| Collaborator capacity | A clean room can include up to 10 collaborators. | None | This includes the creator and up to 9 other collaborators. |

## Uploading a notebook and designating runners

When a collaborator adds a notebook to the clean room:

* They are considered the uploader of that notebook in the clean room.
* When adding a notebook, the uploader must designate which collaborator is the designated runner of the notebook. The designated runner is permitted to run the notebook.
* There can only be one designated runner.
* You can assign yourself as the designated runner of the notebook.

See [Step 3. Add data assets and notebooks to the clean room](/aws/en/clean-rooms/create-clean-room#add-assets)

## Approve a notebook in a clean room

Every notebook requires approval from all collaborators, except the uploader, before executing it.

To check the review status of a notebook:

1. In your Databricks workspace, click  **Catalog**.
2. Click the **Clean Rooms >** button.
3. Select the clean room from the list.
4. Select the notebook you want to run.
5. Click the **People** icon on the right to expand the collaborator section of the notebook details page.
6. The **Reviews** section provides a clear overview of which collaborators have approved, rejected, or have yet to review the notebook.

A difference view is available when a notebook has been changed from a previous version.

When running a notebook version, the following is true:

* You can only run the latest version of a notebook.
* You can only approve or reject the latest version of a notebook.
* Modifying a notebook by adding new content or changing the runner designation creates a new version, which resets the review state for all collaborators.
* A notebook can have a maximum of 10 versions. See [Resource limits](/aws/en/resources/limits).

To access the difference view for a notebook:

1. Click the **Clock icon** on the right to expand the version history of the notebook details page.

To approve or reject a notebook:

1. Click the **Review** button at the upper right.
2. Choose to **Approve** or **Reject** the notebook.

You can update your review up to nine times, for a maximum of ten reviews per collaborator on each notebook version. However, you can always reject a notebook, even if the review limit has been reached.

## Auto-approval rules

Collaborators can set up auto-approval rules for their clean room. With auto-approvals, the following is true:

* You can create auto-approval rules only for notebooks uploaded by other users, not your own. Self-authored notebooks do not require your own approval if you are the designated runner.
* In 2-person clean rooms, you can auto-approve notebooks authored by the other collaborator.
* In clean rooms with more than two collaborators, you can auto-approve notebooks authored by **Anyone** or a specific collaborator.
* Each auto-approval rule designates a single runner for the approved notebook.
* Auto-approval is the default for notebooks uploaded by another collaborator when you are the designated runner.
* Auto-approvals are optional for clean rooms where the designated runner is another collaborator.
* You can add, update, or remove auto-approvals at any time.

note

Auto-approval rules are not available in packaged clean rooms. See [Packaged clean rooms](/aws/en/clean-rooms/packaged-clean-rooms).

To manage auto-approvals:

1. In your Databricks workspace, click  **Catalog**.
2. Click the **Clean Rooms >** button.
3. On the **Clean Rooms** page click the **Gear icon**
4. Select **Configure auto-approvals**.
5. Configure automatic notebook approval based on matching permission rules.

## Run a notebook in a clean room

To run a notebook, check all necessary approvals are in place and that you are the designated runner. Then:

1. Under **Notebooks**, click the notebook to open it in preview mode.
2. Click the **Run** button.
   * You can only run notebooks for which you are the designated runner and which have been approved.
   * It is not necessary to manually approve notebooks that you authored yourself to run them.
   * You can reject a notebook you authored. You must re-approve it before it can be run.
   * You can manage auto-approvals for each notebook. See [Auto-approval rules](#auto).
3. (Optional) On the **Run notebook with parameters** dialog, click **+ Add** to pass parameter values to the notebook job task.
4. Review the notebook.
5. Click **Run**.
6. Click **See details** to view the progress of the run.
   Alternatively, you can view run progress by going to **Runs** on this page or by clicking **Jobs & Pipelines** in the workspace sidebar and going to the **Job runs** tab.
7. View the results of the notebook run.
   The notebook results appear after the run is complete. To view past runs, go to **Runs** and click the link in the **Start time** column.

Even when all collaborators approve a notebook, only the collaborator designated by the uploader as the runner can run it.

### Notebook parameters

The following parameters are automatically passed into the clean room notebook at runtime:

* `cr_central_id`: The central clean room ID.
* `cr_runner_global_metastore_id`: The global metastore ID of the designated runner.
* `cr_runner_alias`: The collaborator alias of the designated runner.
* `cr_<alias>_input_catalog`: The catalog that stores data shared by a specific collaborator, where `alias` represents their clean room alias. For two-party clean rooms created in the UI, this defaults to creator or collaborator, but it is customizable via the API. You can use `cr_<alias>_input_catalog` parameter for local tests with sample tables.
* `cr_output_catalog`: Defines the catalog where you create new output tables. Used in combination with `cr_output_schema`. See [Create an output table](/aws/en/clean-rooms/output-tables#create-an-output-table).
* `cr_output_schema`: Defines the schema where you create output tables. Used in combination with `cr_output_catalog`. See [Create an output table](/aws/en/clean-rooms/output-tables#create-an-output-table).
* `cr_shared_output_schema`: Defines the schema where you create output tables that all collaborators can read, not just the runner. Used in combination with `cr_output_catalog`. Available only when shared output is enabled for the clean room. See [Share output with all collaborators](/aws/en/clean-rooms/output-tables#shared-output).

The above notebook parameters are automatically available as widget values during execution.

* **Python cells**: Reference them using `dbutils.widgets.get`. For example: `dbutils.widgets.get("cr_central_id")`.
* **SQL cells**: Access them with `select :name`. For example: `select :cr_central_id`.

## Call a JAR UDF from a notebook

You can register a custom Java or Scala function from a shared JAR and call it from a clean room notebook using `CREATE TEMPORARY FUNCTION`. See [Run JAR workloads in Databricks clean rooms](/aws/en/clean-rooms/clean-room-jar-task).

## Choose a base environment

Beta

ML and AI base environments are in [Beta](/aws/en/release-notes/release-types). Standard environments are generally available.

When you add a notebook to a clean room, you select a **Base environment** for it. The base environment sets the serverless environment version and the Python libraries that are preinstalled when the notebook runs. All collaborators can see the base environment that each notebook uses.

* **Standard**: The serverless environment with Databricks-provided libraries.
* **ML**: Adds the libraries from Databricks Runtime for Machine Learning. Available for notebooks that run on CPU.
* **AI**: Adds deep learning libraries such as PyTorch and Hugging Face Transformers. Available for notebooks that run on GPU.

Custom base environments are not supported in clean rooms. To learn more about base environments, see [Configure the serverless environment](/aws/en/compute/serverless/dependencies).

You can change the base environment when you update the notebook. The update creates a new notebook version, which all collaborators must approve again. See  [Approve a notebook in a clean room](#approve).

## Run a notebook on serverless GPU

By default, clean room notebooks run on serverless CPU compute. To run model inference or training on shared data, you can run a clean room notebook on serverless GPU compute instead. GPU notebooks run on AI Runtime.

A GPU notebook runs in the same central clean room as other notebooks, with the same approval flow, data access, and output tables. All collaborators can see the accelerator that each notebook uses.

### Requirements

* For accounts on the Enterprise pricing tier, serverless GPU in clean rooms is turned off by default until Databricks turns it on automatically. For the planned date, see [Serverless GPU in clean rooms will soon be on by default for accounts where it's turned off](/aws/en/release-notes/whats-coming#clean-rooms-serverless-gpu-default).

* To turn on serverless GPU in clean rooms, an account admin must enable **Clean Rooms AI Runtime** on the account console **Previews** page. See  [Manage account-level previews](/aws/en/admin/workspace-settings/manage-previews#account). The setting applies to the account of the collaborator who adds the notebook.
* The central clean room must be hosted in one of the following regions:

  + **AWS**: `ca-central-1`, `eu-west-1`, `sa-east-1`, `us-east-1`, `us-east-2`, or `us-west-2`.
  + **Azure**: `eastus` or `westus`.
* The notebook must use a Standard base environment version 4 or above, or an AI base environment. When you select an accelerator, the **Base environment** list shows only these environments. See [Choose a base environment](#base-environment).

GPU compute for AI Runtime can run in a different Geo than the central clean room region, because some GPU types require cross-Geo processing. Cross-Geo processing can incur egress costs and affect data residency. See [Enable cross-Geo processing](/aws/en/resources/databricks-geos#cross-geo-processing).
