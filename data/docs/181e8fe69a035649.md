Genie Search builds and maintains a search index across the sources where your organization keeps its knowledge: Google Drive, Jira, Confluence, SharePoint (Beta), and Workday. Databricks ingests and indexes the content along with each document's permissions, and keeps both current as they change.

With Genie Search, Genie searches one index that covers all of your connected sources, instead of querying each source separately. Genie Search also extends [Genie Ontology](/aws/en/genie/genie-ontology/) beyond Databricks, so Genie can draw on your documents and tickets as context when it answers questions. [Users see only the content they can already open in the source](#permissions).

Workday also powers org directories in Genie One. See [Connect a people source for Genie One](/aws/en/genie/genie-ontology/connect-people-source).

## Requirements

* Databricks account admin privileges
* A workspace in a [supported geo](#supported-regions).
* An admin for each source you connect, such as a Google Workspace admin, an Atlassian admin, or a Microsoft Entra Privileged Role Administrator or Global Administrator, to authorize access. This can be a different person from the Databricks account admin.

## Supported regions

Genie Search stores all of an account's indexed data in one geo. When you connect your first source, select a supported geo in **Data residency Geo**. Your account must have at least one workspace in that geo. Sources you connect later use the same geo. See [Storage and location](#storage).

Genie Search supports the following [Databricks Geos](/aws/en/resources/databricks-geos):

* Americas
* Asia
* Australia and New Zealand
* Europe
* India

The Americas geo includes Canada and Brazil, the Europe geo includes the United Kingdom, and the Asia geo includes South Korea and Indonesia.

Genie Search isn't available in the Mainland China or Middle East and Africa geos, or in AWS GovCloud regions.

## Connect a source

Start each connection from the account console.

1. In the [account console](https://accounts.cloud.databricks.com), click **Genie Ontology**.
2. Click **Connect source**.
3. Select the source.
4. In **Data residency Geo**, select the geo where the source's index is stored. You can select only a geo where your account has a workspace. If the account already has a source, select the same geo. See [Storage and location](#storage).

Then complete the steps for your source:

* Google Drive
* Jira
* Confluence
* SharePoint (Beta)
* Workday

You need a Google Cloud project where you can create a service account, and a Google Workspace admin who can grant domain-wide delegation in the Google Admin console.

1. Create a service account and a JSON key:

   1. In the Google Cloud console, go to **IAM & Admin > Service Accounts**.
   2. Click **Create service account**.
   3. Enter a name and description for the service account, then click **Create and continue**.
   4. Click **Done**. You don't need to grant project-level roles.
   5. On the **Service Accounts** page, click the service account that you created.
   6. On the **Keys** tab, click **Add key > Create new key**.
   7. Select **JSON**, then click **Create**. The JSON key file downloads to your machine.
2. Enable the Google APIs that the service account uses:

   1. In the Google Cloud console, go to **APIs & Services > Library**.
   2. Search for **Google Drive API**, click it, and click **Enable**.
   3. Search for **Admin SDK API**, click it, and click **Enable**.
3. Grant domain-wide delegation:

   1. In the Google Cloud console, copy the service account's **Unique ID** (client ID) from the **Details** tab.
   2. In the [Google Admin console](https://admin.google.com), go to **Security > Access and data control > API controls**.
   3. Under **Domain-wide delegation**, click **Manage domain-wide delegation**.
   4. Click **Add new**.
   5. In **Client ID**, paste the service account's unique ID.
   6. In **OAuth scopes**, enter the following read-only scopes, separated by commas:

      Text

      ```
      https://www.googleapis.com/auth/drive.readonly,https://www.googleapis.com/auth/admin.directory.user.readonly,https://www.googleapis.com/auth/admin.directory.group.readonly,https://www.googleapis.com/auth/admin.reports.audit.readonly
      ```
   7. Click **Authorize**.
4. In the **Connect Google Drive** dialog in Databricks, paste the full contents of the JSON key, including the opening and closing braces, into **Service account JSON**.
5. In **Admin email**, enter the email of a Google Workspace admin who can read users, groups, and shared drives. The service account acts as this admin.
6. Click **Start ingestion**.

If you skip any of the delegation, API, or scope steps, ingestion can fail or miss content until you finish that setup.

The user who authorizes the connection must have the `ADMINISTER JIRA` and `BROWSE USERS AND GROUPS` global permissions. See [Global permissions](https://support.atlassian.com/jira-cloud-administration/docs/manage-global-permissions/) in the Atlassian documentation.

1. In the **Connect Jira** dialog, copy the callback URL.
2. In the [Atlassian developer console](https://developer.atlassian.com/console/myapps/), click **Create > OAuth 2.0 integration**, enter a name, and click **Create**. To use an existing OAuth app instead, open it and add the scopes and callback URL in the following steps.
3. Go to **Permissions > Jira API** (under **API scopes**) and click **Add**.
4. Click **Classic Scopes > Edit Scopes**, then add `read:jira-work` and `read:jira-user`.
5. Click **Granular Scopes > Edit Scopes**, then add the following scopes:
   * `read:project-role:jira`
   * `read:project-category:jira`
   * `read:project:jira`
   * `read:user:jira`
   * `read:avatar:jira`
   * `read:group:jira`
   * `read:application-role:jira`
   * `read:workflow:jira`
   * `read:issue-security-level:jira`
   * `read:issue-security-scheme:jira`
   * `read:audit-log:jira`
   * `read:sprint:jira-software`
   * `read:board-scope:jira-software`
   * `read:board-scope.admin:jira-software`
6. Go to **Authorization**, click **Add**, and enter the callback URL that you copied.
7. Go to **Settings** and copy the **Client ID** and **Secret**.
8. In the **Connect Jira** dialog, enter the **Jira site URL**, including `https://`. For example, `https://yourcompany.atlassian.net`. Don't add a path or trailing slash.
9. Enter the **Client ID** and **Client secret** of your OAuth app.
10. Click **Authorize**, choose the Jira site, and click **Accept**.
11. Click **Start ingestion**.

The user who authorizes the connection must have the `CONFLUENCE ADMINISTRATOR` global permission and access to every space you want to index. See [Manage global permissions](https://support.atlassian.com/confluence-cloud/docs/manage-global-permissions/) in the Atlassian documentation.

1. In the **Connect Confluence** dialog, copy the callback URL.
2. In the [Atlassian developer console](https://developer.atlassian.com/console/myapps/), click **Create > OAuth 2.0 integration**, enter a name, and click **Create**. To use an existing OAuth app instead, open it and add the scopes and callback URL in the following steps.
3. Go to **Permissions > Confluence API** (under **API scopes**) and click **Add**.
4. Click **Granular Scopes > Edit Scopes**, then add the following scopes:
   * `read:page:confluence`
   * `read:attachment:confluence`
   * `read:space:confluence`
   * `read:configuration:confluence`
   * `read:label:confluence`
   * `read:space.permission:confluence`
   * `read:content.permission:confluence`
   * `read:content-details:confluence`
   * `read:group:confluence`
   * `read:user:confluence`
   * `read:audit-log:confluence`
   * `read:analytics.content:confluence`
5. Go to **Authorization**, click **Add**, and enter the callback URL that you copied.
6. Go to **Settings** and copy the **Client ID** and **Secret**.
7. In the **Connect Confluence** dialog, enter the **Confluence site domain**, without `https://`. For example, `yourcompany.atlassian.net`.
8. Enter the **Client ID** and **Client secret** of your OAuth app.
9. Click **Authorize**, choose the Confluence site, and click **Accept**.
10. Click **Start ingestion**.

Beta

SharePoint in Genie Search is in [Beta](/aws/en/release-notes/release-types). To use it, an account admin must turn on the **Genie Search Index (SharePoint)** preview in the [account console](https://accounts.cloud.databricks.com). See  [Manage account-level previews](/aws/en/admin/workspace-settings/manage-previews#account).

You need a Microsoft Entra admin with the Privileged Role Administrator or Global Administrator role to grant admin consent, because the application requests Microsoft Graph application permissions. Genie Search reads SharePoint with app-only access and authenticates with a certificate. Client secrets aren't supported.

To see SharePoint results, each user's Databricks username must match their user principal name (UPN), email address, or an email alias in Microsoft Entra ID.

1. Register a Microsoft Entra ID application and copy its **Application (client) ID** and **Directory (tenant) ID**. See [Step 3: Create a Microsoft Entra ID application](/aws/en/ingestion/lakeflow-connect/sharepoint-source-setup-m2m#create-client).
2. Add a certificate to the application. Keep the PEM certificate file and its private key file. The private key must be an unencrypted PKCS #8 key. To create one, see the **Certificate** tab in [Step 3: Create a Microsoft Entra ID application](/aws/en/ingestion/lakeflow-connect/sharepoint-source-setup-m2m#certificate).
3. Grant the application API permissions:
   1. In the app registration, click **API permissions**.
   2. Click **Add a permission > Microsoft Graph > Application permissions**, then add the following permissions:
      * `Sites.FullControl.All`
      * `User.Read.All`
      * `GroupMember.Read.All`
      * `Member.Read.Hidden`
   3. Click **Add permissions**.
   4. Click **Add a permission > SharePoint > Application permissions**, then add `Sites.FullControl.All`.
   5. Click **Add permissions**.
   6. Click **Grant admin consent** for your organization, then click **Yes**.
4. In the **Connect SharePoint** dialog in Databricks, enter the following:
   * **Directory (tenant) ID**: The tenant ID of the application.
   * **Application (client) ID**: The client ID of the application.
   * **SharePoint URL**: The root URL of your SharePoint, without a site path. For example, `https://contoso.sharepoint.com`.
   * **Certificate**: Paste the PEM certificate that you added to the application, or click **Upload certificate**.
   * **Private key**: Click **Upload private key** and select the private key file.
5. Click **Start ingestion**.

If the dialog shows "The Entra app is missing access," add the listed permissions to the Microsoft Entra ID application. Ingestion can fail or miss content until the application has them.

Certificates expire, and SharePoint sources can't be re-authorized. To replace the certificate, remove the source and connect it again. See [Manage sources](#pause-or-remove-a-source).

To connect Workday for org directories, see [Connect a people source for Genie One](/aws/en/genie/genie-ontology/connect-people-source).

Initial indexing can take hours or days, depending on how much content is in the source. The source status is **Provisioning** until indexing finishes, then **Searchable**. If setup fails, the status is **Failed**.

## Use indexed content

After a source is **Searchable**, Genie One chat uses Genie Search automatically when it answers questions. Users can also find indexed content in Genie One Discover, alongside Databricks assets. See [Use Genie Search in Genie One](/aws/en/genie-one/search).
