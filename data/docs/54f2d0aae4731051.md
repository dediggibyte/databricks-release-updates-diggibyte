Beta

This feature is in [Beta](/aws/en/release-notes/release-types). To use it, a workspace admin must turn on **Project-Scoped Shared Compute** from the **Previews** page. See [Manage Databricks previews](/aws/en/admin/workspace-settings/manage-previews).

With Shared Serverless, notebooks and files in the same Git folder or bundle share serverless compute and a Python environment in the editor. To customize the environment, add a `pyproject.toml` file at the folder root. Choose the compute option for your Git folder or bundle:

* [Git folders](#git-folder-serverless), with Shared Serverless for Git Folders.
* [Declarative Automation Bundles](#asset-bundles-serverless), with Shared Serverless for Asset Bundles.

## Requirements

* Your workspace must meet the [serverless compute requirements](/aws/en/compute/serverless/#requirements).
* Open your Git folder or bundle in the Git folder editor or the bundle editor. See [Create and manage Git folders](/aws/en/repos/git-operations-with-repos) and [Author bundles in the workspace](/aws/en/dev-tools/bundles/workspace-author).
* Shared Serverless requires serverless environment version 5 or above.

## Shared compute and environment

* Notebooks and files in the same Git folder or bundle share compute and a Python environment in the editor. An optional `pyproject.toml` file at the folder root defines the shared environment.
* Only notebooks and files inside the associated Git folder or bundle can attach to its shared compute resource.
* Shared compute resources are isolated by user. Only the user who first attaches a notebook or file to a shared compute resource can run workloads on it.
* Notebook execution remains isolated. Python variables defined in one notebook are not available in another notebook.
* A [web terminal](/aws/en/compute/web-terminal) opened from an attached notebook or file runs on the same compute resource.

## Shared Serverless for Git Folders

Use Shared Serverless for Git Folders to work with notebooks and files in a [Git folder](/aws/en/repos/).

### Attach notebooks and files in the Git folder editor

1. In the workspace sidebar, click **Workspace** and navigate to the Git folder.
2. Click **Open in editor**.
3. Open a notebook or file in the Git folder.
4. Click the compute drop-down menu.
5. Select **Shared Serverless for Git Folders**.
6. Run the notebook or file to start the compute resource.

To use the same compute from another notebook or file, open it in the same Git folder and select **Shared Serverless for Git Folders**.

### Collaborate through Git

Databricks recommends that each collaborator [clone the repository](/aws/en/repos/git-operations-with-repos#clone-repo) into a Git folder in their personal workspace folder. Each collaborator then gets a separate compute resource and environment for their clone.

Use branches, commits, pushes, and pulls to exchange changes through the remote Git repository. See [Collaborate in Git folders](/aws/en/repos/git-operations-with-repos#best-practices).

## Shared Serverless for Asset Bundles

Use Shared Serverless for Asset Bundles to work with notebooks and files in a [bundle in the workspace](/aws/en/dev-tools/bundles/workspace-author). The bundle root contains `databricks.yml` and can contain a `pyproject.toml` file that defines the shared environment.

### Attach notebooks and files in the bundle editor

1. In the workspace sidebar, click **Workspace** and navigate to the bundle.
2. To the right of the bundle name, click **Open in editor**.
3. Open a notebook or file in the bundle.
4. Click the compute drop-down menu.
5. Select **Shared Serverless for Asset Bundles**.
6. Run the notebook or file to start the compute resource.

To use the same compute from another notebook or file, open it in the same bundle and select **Shared Serverless for Asset Bundles**.

To collaborate through Git, have each collaborator clone the repository into a Git folder in their personal workspace folder. See [Collaborate through Git](#collaborate-through-git).

## Manage the environment with `pyproject.toml`

Shared Serverless uses the `pyproject.toml` file at the Git folder or bundle root to manage Python dependencies for the project. Standard serverless notebooks use dependencies configured for each notebook in the **Environment** side pane.

Create the root `pyproject.toml` file and set its serverless environment version before managing its dependencies. See [Create and edit `pyproject.toml`](#edit-pyprojecttoml). You can then add dependencies with notebook commands or edit the file directly.

### Use notebook commands

1. Open a notebook attached to **Shared Serverless for Git Folders** or **Shared Serverless for Asset Bundles**.
2. Run `%uv add <package>` to add a dependency to the root `pyproject.toml` file. For example:

   Python

   ```
   %uv add cowsay
   ```

The command updates `pyproject.toml`, `uv.lock`, and the shared environment. You do not need to run `%uv sync` after `%uv add`. Use `%uv sync` to apply changes made directly to `pyproject.toml`.

### Create and edit `pyproject.toml`

1. Open a notebook attached to **Shared Serverless for Git Folders** or **Shared Serverless for Asset Bundles**.
2. Open the **Environment** side pane.
3. In the **Managed by pyproject.toml** card, click  **Create pyproject.toml** to create the root file. If the file already exists, click  **View pyproject.toml**. The file opens in the editor.
4. Edit the `dependencies` list. Keep the generated `[tool.databricks.environment]` section, or add it if missing. Set `environment_version` to a supported version (5 and above). For example:

   Toml

   ```
   [project]

   name = "my-project"

   version = "0.1.0"

   dependencies = [

   "simplejson==3.18.1",

   ]

   [tool.databricks.environment]

   environment_version = "5"
   ```
5. Click **Apply** at the top of the `pyproject.toml` file editor.

The updated environment is available to notebooks and files attached to the same shared compute resource. To inspect the environment, open the **Environment** side pane. See [Configure the serverless environment](/aws/en/compute/serverless/dependencies) for information about serverless environment versions and installed dependencies.

## Schedule a notebook

When you schedule a notebook attached to Shared Serverless from the Git folder or bundle editor, Databricks uses the root `pyproject.toml` file as the job's project environment if the file exists. Deploy the bundle as described in the following steps.

1. In the Git folder or bundle editor, open a notebook attached to Shared Serverless.
2. If the Git folder or bundle has a root `pyproject.toml` file, verify that it declares the dependencies needed by the task.
3. Click **Schedule**.
4. In the **Compute** drop-down list, select serverless compute.
5. Configure the schedule and click **Create**.

After you click **Create**, check the job configuration:

* **Git folder:** If the Git folder has a root `pyproject.toml` file, verify that **Project environment** in the job's task configuration points to it. To change the selection, see [Configure environment for job tasks](/aws/en/compute/serverless/dependencies#libraries).
* **Bundle:** The bundle editor opens a generated job YAML file in the `resources/` folder.

  1. If the bundle has a root `pyproject.toml` file, verify that `project_environment` under the environment's `spec` points to it, relative to the generated YAML file. See [Configure a project environment in a bundle](/aws/en/compute/serverless/dependencies#project-environment-bundle).
  2. [Deploy the bundle](/aws/en/dev-tools/bundles/workspace-deploy#deploy) to create the job.

  Schedules are paused by default in development mode. See [Declarative Automation Bundles deployment modes](/aws/en/dev-tools/bundles/deployment-modes).

For notebook scheduling options, see [Create and manage scheduled notebook jobs](/aws/en/notebooks/schedule-notebook-jobs).

## Limitations

* Compute sharing is scoped to a [serverless usage policy](/aws/en/admin/usage/budget-policies). Notebooks and files in the same Git folder or bundle that use different usage policies are assigned separate compute resources instead of sharing one.
