Beta

Lakewatch is in [Beta](/aws/en/release-notes/release-types). Workspace admins can control access to this feature from the **Previews** page. See  [Manage workspace-level previews](/aws/en/admin/workspace-settings/manage-previews#workspace).

Lakewatch helps security teams bring in security logs, detect threats, and investigate and respond to alerts, all on Databricks. Start with the walkthrough to see the full workflow, or go straight to the task you need.

Before you start

Lakewatch is set up one time for each workspace. The first time anyone opens Lakewatch, a guided setup flow creates its environment, which requires `CREATE CATALOG` on the metastore, or `MANAGE` and `CREATE SCHEMA` on an existing catalog. See [Set up Lakewatch for your workspace](/aws/en/lakewatch/admin/set-up-workspace).

## Detect and investigate threats

Write or install detection rules, respond to the alerts they create, and search your data for activity.

* + [Detect threats with SQL rules](/aws/en/lakewatch/detections/)
  + Write detection rules that run SQL on a schedule and generate signals when conditions match.
* + [Install prebuilt detections](/aws/en/lakewatch/content-library/)
  + Browse detection rules that Databricks authors and install them into your workspace.
* + [Triage and respond to alerts](/aws/en/lakewatch/alerts/)
  + Work through alerts that group related signals, and export them to Jira, ServiceNow, Tines, or a webhook.
* + [Search across your security data](/aws/en/lakewatch/queries/)
  + Search and filter events with SQL, view them on a timeline, and inspect individual rows.
* + [Investigate threats with AI using Genie](/aws/en/lakewatch/genie/)
  + Use Genie Code for in-product help and Genie Agents for multi-step threat investigations.
