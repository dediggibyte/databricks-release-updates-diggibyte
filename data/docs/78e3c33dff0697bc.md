## Data Transfer & Connectivity

Customers using Databricks Serverless products may incur data transfer costs when they move data between different regions or availability zones within the same cloud, move data out of a cloud, or require public or private connectivity from their VPCs. Additionally, in certain high-throughput scenarios egress to client users and applications may also result in data egress charges. Please refer to the links below to see detailed information about data transfer pricing by cloud and type of data transfer.

[Databricks Data Transfer Pricing](https://www.databricks.com/sites/default/files/2024-08/databricks-data-transfer-pricing.pdf)

[SAP Databricks CU consumption](https://www.databricks.com/sites/default/files/2025-09/data-transfer-pricing-pdf-for-sap-databricks-with-sap-azure.pdf)

Networking billing product documentation ([AWS](https://docs.databricks.com/aws/en/security/network/serverless-network-security/cost-management), [Azure](https://learn.microsoft.com/en-us/azure/databricks/security/network/serverless-network-security/cost-management))

## Data Transfer & Connectivity FAQ

When do I incur Databricks data transfer costs?

There are two ways customers may incur Databricks data transfer costs - Data transfer from Databricks Serverless products to your resources, and, in certain high-throughput use cases, data egress from Databricks back to client users and applications. Please refer to product documentation ([AWS](https://docs.databricks.com/aws/en/security/network/serverless-network-security/cost-management), [Azure](https://learn.microsoft.com/en-us/azure/databricks/security/network/serverless-network-security/cost-management)) for details.

| Connection type | Description | Billed |
| --- | --- | --- |
| **Private Connectivity (/GB)** | Charges for per GB data processed. [Databricks private connectivity](https://docs.databricks.com/aws/en/security/network/) allows you to connect to cloud resources without using a public IP. | Yes |
| **Private Connectivity (/hour)** | Charges for per hour private endpoint fees. [Databricks private connectivity](https://docs.databricks.com/aws/en/security/network/) allows you to connect to cloud resources without using a public IP. | Yes\* |
| **Public Connectivity (/GB)** | Charges for per GB data processed. [Databricks public connectivity](https://docs.databricks.com/aws/en/security/network/) allows you to connect to cloud resources or the internet using public IP addresses. | Yes |
| **Data Egress (/GB)** | Data egress includes in-region data transfer between availability zones or from IPv4 address, data transfer to a different region, and data transfer to the internet or other clouds. | Yes |

\* Please note that inbound and outbound data processed charges for [Azure Private Link](https://azure.microsoft.com/en-us/pricing/details/private-link/) are waived indefinitely.

What is Databricks Public Connectivity and how is it charged?

Databricks [Public Connectivity](https://docs.databricks.com/en/security/network/serverless-network-security/index.html) enables connecting to cloud resources or the internet using public IPs. Customers will be charged for the volume of data transferred through Databricks Public Connectivity.

What is Databricks Private Connectivity and how is it charged?

Databricks [Private Connectivity](https://docs.databricks.com/en/security/network/serverless-network-security/index.html) allows customers to connect to cloud resources without using a public IP. AWS and GCP customers that use Databricks Private Connectivity with Serverless workloads will incur a per-hour charge for each private endpoint and a per-GB charge for the volume of data transferred through these endpoints. Azure customers that use Databricks Private Connectivity with serverless workloads will incur a per-hour charge for each private endpoint.

Which products will these costs apply to?

All Databricks Serverless products incur data transfer costs to your resources. Data transfer transfer costs for egress back to client users and applications is charged for certain high-throughput use cases. Please refer to the [product documentation](https://docs.databricks.com/aws/en/security/network/serverless-network-security/cost-management) for additional information on high-throughput use cases.

When will billing begin?

Today, AWS and Azure customers are billed for data transfer from Databricks Serverless to their own resources. Separately, billing for data egress to external users and applications for certain high-throughput use cases like OpenSharing SecureConnect and Lakebase, is now live on AWS and Azure. GCP is expected to follow at a later date.

How do data transfer costs show up on my bill?

AWS and GCP customers will be charged by Databricks using the applicable Databricks data transfer SKUs. Azure Databricks customers are billed directly by Azure using the applicable Azure SKUs.
