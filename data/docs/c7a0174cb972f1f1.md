Artifact Registry stores container images as governed assets in Unity Catalog. The images are stored in the same region as the Unity Catalog metastore. Use it to push images with standard Docker commands, control access with Unity Catalog privileges, and make images available to supported Databricks workloads.

If an AI Runtime workload runs in a region other than your workspace's region, Databricks might cache your custom Docker image in that region to speed up later workloads. Databricks automatically deletes a cached image after it goes unused for 30 days.

## Key concepts

* **Artifact:** A named container image stored in Unity Catalog, identified by a three-level name in the format `catalog.schema.artifact`.
* **Tag:** A mutable alias that points to an artifact version using the format `catalog.schema.artifact:tag`. Pushing a tag again can change the version that the tag resolves to. For repeatable deployments, avoid mutable tags such as `latest` and reference a digest when the workload accepts digest references.
* **Image digest:** An immutable, content-addressed identifier for a specific version of an artifact.
* **Image acceleration:** An optimization that Databricks applies automatically after you push an eligible image to Artifact Registry. This process converts the image to a format designed to reduce pull latency for supported workloads. To check an artifact version's image acceleration status, see [Check image acceleration status](/aws/en/artifact-registry/get-started#image-acceleration-status).

## How Artifact Registry works

Publishers and users work with container images in Artifact Registry through the following lifecycle:

1. **Build and push:** A publisher builds an image, tags it with a three-level Unity Catalog name in the format `catalog.schema.artifact:tag`, and pushes it to the workspace registry. See [Artifact name requirements](/aws/en/artifact-registry/get-started#image-name-requirements) and [Push an image](/aws/en/artifact-registry/get-started#push-an-image).
2. **Govern:** Artifact Registry stores the image under the specified Unity Catalog catalog and schema. Unity Catalog privileges control who can publish, discover, and read the image. See [Grant permissions](/aws/en/artifact-registry/get-started#artifact-registry-permissions).
3. **Discover:** Users browse images and versions in Catalog Explorer or list them with the Databricks CLI, and check image acceleration status. See [Discover images and versions](/aws/en/artifact-registry/get-started#list-artifacts-and-versions).
4. **Use:** Users reference an image when they create supported Databricks workloads, such as jobs that run custom container images. See [Use images in supported Databricks workloads](/aws/en/artifact-registry/get-started#supported-workloads).

After you publish images, you can transfer artifact ownership and delete versions that you no longer need. See [Transfer ownership of an artifact](/aws/en/artifact-registry/get-started#transfer-ownership) and [Delete images](/aws/en/artifact-registry/get-started#delete-images).

## Limitations

The following limitations apply:

**Availability**

* Your workspace and its Unity Catalog metastore must be in the same region. If the regions differ, you cannot use Artifact Registry from that workspace.
* Artifact Registry is available in the following regions:

  + `ap-northeast-1`
  + `ap-northeast-2`
  + `ap-south-1`
  + `ap-southeast-1`
  + `ap-southeast-2`
  + `ca-central-1`
  + `eu-central-1`
  + `eu-west-1`
  + `eu-west-2`
  + `eu-west-3`
  + `sa-east-1`
  + `us-east-1`
  + `us-east-2`
  + `us-west-2`

**Supported use**

* You can use images in Artifact Registry only with supported Databricks workloads. See [Use images in supported Databricks workloads](/aws/en/artifact-registry/get-started#supported-workloads).
* You cannot use Docker or another registry client to pull these images or download image blobs directly.

**Authentication**

* The workspace OAuth access token used for Docker authentication expires after one hour. A push that takes longer can fail authorization for a layer uploaded after expiration. With the Docker credential helper, retry the push to request a new token. If you used `docker login`, generate a new token and sign in again before retrying.

**Image acceleration**

* Images larger than 30 GB cannot be converted for image acceleration.
* Image acceleration does not expose a failed conversion state. See [Check image acceleration status](/aws/en/artifact-registry/get-started#image-acceleration-status).

**Discovery and management**

* Catalog Explorer does not support deleting images. To delete images, use the Databricks CLI. See [Delete images](/aws/en/artifact-registry/get-started#delete-images).
* The registry endpoint does not support Open Container Initiative (OCI) tag-list requests or delete requests.
* You cannot remove a tag without deleting the version that it points to. To point a tag at a different version, push that version with the tag.
* When more than 10 tags point to the same digest, Catalog Explorer, the Databricks CLI, and the Software Artifacts API show only 10 of them.

**Artifact names**

* Artifact names have character and formatting restrictions. See [Artifact name requirements](/aws/en/artifact-registry/get-started#image-name-requirements).

## Audit logging

Artifact Registry records artifact discovery, ownership changes, deletions, and image pushes and pulls in workspace audit logs. These events use the `service_name` value `unityCatalog`. For event names and request parameters, see [Artifact Registry events](/aws/en/admin/account-settings/audit-logs#artifact-registry).

To query these events in `system.access.audit`, see [Audit log system table reference](/aws/en/admin/system-tables/audit-logs).
