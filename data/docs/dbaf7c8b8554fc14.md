Beta

This feature is in [Beta](/aws/en/release-notes/release-types). To use it, an account admin must turn on **Impact Analysis** from the account console **Previews** page. See  [Manage account-level previews](/aws/en/admin/workspace-settings/manage-previews#account).

Impact analysis shows the downstream "blast radius" of a table or column before you change it. On a table's **Lineage** tab in Catalog Explorer, it lists the assets that depend on the table or one of its columns, with certified assets first and the rest ordered by impact level. The list uses [lineage in Unity Catalog](/aws/en/data-governance/unity-catalog/data-lineage) data and shows each asset's impact level, owner, and certification status.

You can run impact analysis manually from the **Lineage** tab, or use Genie Code to summarize the impact and export a CSV of impacted assets and owners. Genie Code might process data outside your workspace's Geo if [cross-Geo processing](/aws/en/resources/databricks-geos#cross-geo-processing) is enabled. See [Genie Code](/aws/en/genie-code/).

## When to use impact analysis

Run impact analysis before a change that can break or alter results for downstream consumers. The following table groups common changes by what the owners of downstream assets need to do.

| Downstream owners need to | Example changes |
| --- | --- |
| Update their code | Deprecate, rename, or move a table. Change a table's schema. Deprecate or rename a column, or change its data type. |
| Request access | Apply a [column mask or row filter](/aws/en/data-governance/unity-catalog/filters-and-masks/). Revoke or restructure [privileges](/aws/en/data-governance/unity-catalog/manage-privileges/) on a table. |
| Monitor their results | Change partitioning or clustering keys. Resolve a data quality issue, such as stale or incomplete data. Replace an upstream source. |

## Requirements

* You must have permission to view lineage for the table. See [lineage permissions](/aws/en/data-governance/unity-catalog/data-lineage#permissions).
* To summarize impact with Genie Code, Genie Code must be available in your workspace. See [Genie Code](/aws/en/genie-code/).

## Run impact analysis

1. In your Databricks workspace, click  **Catalog**.
2. Browse or search for the table, and click the table name.
3. Click the **Lineage** tab.
4. Click **Conduct impact analysis**.

   The lineage list switches to the impact view and shows table-level impact. If Genie Code is available, the Genie Code panel also opens. See [Summarize impact with Genie Code](#genie-code).
5. (Optional) To analyze one column, click the **Table-level** selector, select **Column-level**, and then search for and select the column.
6. (Optional) Narrow the list by text, asset type, **Impact level**, or **Owners**.

The list shows the assets downstream of the table or column. If nothing depends on it, the view shows **No downstream dependencies**. Results are approximate, and new dependencies can take a few days to appear, so recent or rarely used dependencies might be missing. Don't treat an empty list as proof that a change is safe.

## Understand the results

Each row is a downstream asset. Supported downstream asset types are tables, columns, notebooks, jobs, pipelines, queries, dashboards, Genie Agents, alerts, and apps. The list includes the following columns:

* **Name**: The asset name. Certified assets show a certification badge. See [Flag data as certified or deprecated](/aws/en/data-governance/unity-catalog/certify-deprecate-data).
* **Impact level**: **Critical**, **High**, **Medium**, or **Low**, based on how often the asset and everything downstream of it is read. A job, notebook, or pipeline takes the highest impact level of the tables it writes.
* **Depth**: How many levels downstream the asset is. Direct dependents are at depth 1.
* **Last activity**: The most recent lineage activity that connects the asset to the table or column.
* **Owner**: The asset owner. Columns have no owner.
* **Workspace name**: The workspace the asset belongs to. This column is available only if your account has a [custom URL](/aws/en/admin/account-settings/custom-url), and it's hidden by default. To show it, click  **Select columns** and select **Workspace Name**.

Certified assets appear first, followed by the rest in order of impact level.

Assets that you don't have permission to view appear as masked rows at the end of the list, so you still see how many assets a change affects. If your account has a [custom URL](/aws/en/admin/account-settings/custom-url), the list also includes dependencies in other workspaces. Assets in other workspaces that can't be shown appear as a count.

## Summarize impact with Genie Code

Genie Code is optional, and the impact view works without it. When Genie Code is available, **Conduct impact analysis** also opens it in a separate panel with the prompt **Summarize the impact of changing** and the table name. You can edit the prompt before you send it.

After you send the prompt, Genie Code returns:

* **A summary of the impact**: The number of downstream assets, how many are certified or deprecated, a breakdown by asset type, and the number of users and recent queries on the impacted assets.
* **The top impacted dependencies**: Up to 10 assets, with their impact level and owner.
* **Areas of risk**: For example, high-impact and certified downstream assets.

To analyze a column, name the column in your prompt, or click **Conduct impact analysis for a column**. You can also ask Genie Code about the impact of changing a table from anywhere in Catalog Explorer.

To export the impacted assets, click the suggested follow-up **Generate a CSV with a list of impacted assets and owners**, and then click **Download CSV**. The CSV includes the asset name, asset type, owner, impact level, certification status, and URL for each asset. It leaves out masked assets and assets in other workspaces, so it might not list every impacted asset.

## Limitations

* Impact analysis supports only tables and columns. To see the dependencies of other objects, use [Lineage in Unity Catalog](/aws/en/data-governance/unity-catalog/data-lineage).
* Impact analysis shows only downstream assets. To trace upstream sources, use the [lineage graph](/aws/en/data-governance/unity-catalog/data-lineage#view-lineage-ce).
* Results include up to 1,000 downstream assets. For tables with more downstream assets, the list is incomplete.
* Results go up to 10 levels downstream for tables. For columns, results go up to 5 or 10 levels downstream, depending on the region.
* Direct dependents (depth 1) are based on lineage from the last year. Deeper levels are based on lineage from the last 35 days.
* Results are approximate. New dependencies can take a few days to appear.

* Impact analysis isn't available in AWS GovCloud regions.
