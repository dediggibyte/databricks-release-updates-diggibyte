Feature Views enable you to define and compute features from data sources. Features can be defined using a variety of sources (Delta table, Kafka Stream, and request-time data) and computations (time-windowed aggregations, simple column selections, and more). This guide covers the following workflows:

* **Feature development** workflow
  + Use `create_feature` to define Unity Catalog feature objects that can be used in model training and serving workflows.
  + Alternatively, construct `Feature` objects locally and use `register_feature` to persist them to Unity Catalog later. Locally constructed features can be used with `create_training_set` before registration.
* **Model training** workflow
  + Use `create_training_set` to calculate point-in-time aggregated features for machine learning. For detailed documentation on training with Feature Views, see [Train models with Feature Views](/aws/en/machine-learning/feature-store/train-with-declarative-features).
* **Feature materialization and serving** workflow
  + After defining a feature with `create_feature` or retrieving it using `get_feature`, you can use `materialize_features` to materialize the feature or set of features to an offline store for efficient reuse, or to an online store for online serving.
  + Use `create_training_set` with the materialized view to prepare an offline batch training dataset.

For API details, see [Feature Views API reference](/aws/en/machine-learning/feature-store/feature-views-api-reference).

## Streaming features

Use streaming features when feature values must update continuously instead of on a batch schedule. Streaming and batch features use the same `Feature` constructors, aggregation functions, and training and serving workflows.

Streaming features do not materialize to an offline store. For training and batch inference, Databricks calculates feature values from the source.

Streaming features have the following requirements:

* You must provide an `online_config`. Streaming features do not support `offline_config`.
* You cannot combine streaming and batch features in one `materialize_features` call. Make a separate call for each trigger type.
* You can use `transformation_sql` only with `StreamSource`, not `DeltaTableSource`.
* Streaming materialization processes only records that arrive after the pipeline starts and does not backfill historical records. Rolling-window aggregates return complete results only after the first full window of data arrives.

### Choosing a streaming feature source

Choose a source based on your freshness requirements and existing ingestion setup:

* Use a `StreamSource` when sub-second freshness is the priority. `StreamSource` features provide a p99 end-to-end latency of 200 milliseconds. First [set up a Stream](/aws/en/machine-learning/feature-store/streams), then reference it using a `StreamSource`. Stream sources support Kafka as input and automatically maintain an ingestion Delta table as a historical copy of the data for training.
* Use a `DeltaTableSource` when you already have a low-latency ingestion path into a Delta table. Expect freshness on the order of tens of seconds.
* Use Zerobus to populate a `DeltaTableSource` when you do not already have a low-latency ingestion path. Zerobus ingestion takes on the order of tens of seconds, so expect sub-minute feature freshness.

### Define a streaming feature using a StreamSource

A `StreamSource` references a Stream by its three-part name (`catalog.schema.stream_name`). A Stream is not a Unity Catalog securable object, but it is scoped to a Unity Catalog schema and access is governed by the Stream's ingestion table. Column references in entity, timeseries, and function definitions must be prefixed with `value.` or `key.` to indicate which part of the Kafka message to read. Nested fields are supported using dot notation (for example, `value.user.address.city`).

Python

```
from databricks.feature_engineering import FeatureEngineeringClient  
from databricks.feature_engineering.entities import (  
    StreamSource,  
    Feature,  
    AggregationFunction,  
    Sum,  
    RollingWindow,  
)  
from datetime import timedelta  
  
client = FeatureEngineeringClient()  
  
stream_source = StreamSource(  
    full_name="my_catalog.my_schema.my_stream",  
)  
  
feature = Feature(  
    name="user_purchase_sum",  
    source=stream_source,  
    entity=["value.user_id"],  
    timeseries_column="value.event_time",  
    function=AggregationFunction(  
        operator=Sum(input="value.amount"),  
        time_window=RollingWindow(window_duration=timedelta(hours=1)),  
    ),  
)
```

### Define a streaming feature using a DeltaTableSource

To materialize a feature defined on a `DeltaTableSource` as a streaming feature, pass `StreamingMode` as the trigger to `materialize_features`. The feature definition uses the same APIs as a batch feature backed by a `DeltaTableSource`. Delta table sources support aggregation and column selection features.

The source Delta table must have [change data feed](/aws/en/tables/features/change-data-feed) (CDF) enabled by setting `delta.enableChangeDataFeed=true`.

The following example defines and materializes an aggregation feature with a Delta table source.

Python

```
from databricks.feature_engineering import FeatureEngineeringClient  
from databricks.feature_engineering.entities import (  
    DeltaTableSource,  
    AggregationFunction,  
    OnlineStoreConfig,  
    Sum,  
    RollingWindow,  
    StreamingMode,  
)  
from datetime import timedelta  
  
client = FeatureEngineeringClient()  
  
source = DeltaTableSource(  
    catalog_name="my_catalog",  
    schema_name="my_schema",  
    table_name="transactions",  
)  
  
feature = client.create_feature(  
    catalog_name="my_catalog",  
    schema_name="my_schema",  
    name="user_purchase_sum",  
    source=source,  
    entity=["user_id"],  
    timeseries_column="event_time",  
    function=AggregationFunction(  
        operator=Sum(input="amount"),  
        time_window=RollingWindow(window_duration=timedelta(hours=1)),  
    ),  
)  
  
online_config = OnlineStoreConfig(  
    catalog_name="my_catalog",  
    schema_name="my_schema",  
    table_name_prefix="streaming_features",  
    online_store_name="my_online_store",  
)  
  
client.materialize_features(  
    features=[feature],  
    online_config=online_config,  
    trigger=StreamingMode(),  
)
```

### Use a Delta table populated by Zerobus

A Delta table populated by [Zerobus](/aws/en/ingestion/zerobus-overview) can serve as a streaming feature source. Zerobus does not set `delta.enableChangeDataFeed=true` automatically. You must set this property manually on the target Delta table before using it as a streaming feature source.

### Filter conditions on streaming sources

Use `filter_condition` to filter rows before aggregation for either a `StreamSource` or `DeltaTableSource`.

Python

```
stream_source = StreamSource(  
    full_name="my_catalog.my_schema.my_stream",  
    filter_condition="value.event_type = 'purchase'",  
)
```

### Transform a StreamSource

`transformation_sql` applies a Spark SQL projection before aggregation or column selection, using dot-prefixed references to the `key` and `value` structs. It supports only row-wise expressions. For the full list of supported and unsupported operations, see [Supported `transformation_sql` expressions](/aws/en/machine-learning/feature-store/feature-views-api-reference#transformation-sql-expressions).

When you set `transformation_sql`, you must also provide `dataframe_schema`: the Spark `StructType` JSON of the projected output. Rather than writing this schema by hand, you can also derive it by running the same projection against the Stream's [ingestion table](/aws/en/machine-learning/feature-store/streams#ingestion-table-schema), which exposes the `key` and `value` structs. By specifying `LIMIT 0`, the `SELECT` statement returns the schema without reading any data:

Python

```
from databricks.feature_engineering.entities import StreamSource  
  
transformation_sql = (  
    "value.amount * value.conversion_rate AS converted_amount, "  
    "struct(value.user_id AS user_id, value.event_time AS time) AS event"  
)  
  
ingestion_table = "my_catalog.my_schema.events_ingestion"  
dataframe_schema = spark.sql(  
    f"SELECT {transformation_sql} FROM {ingestion_table} LIMIT 0"  
).schema.json()  
  
stream_source = StreamSource(  
    full_name="my_catalog.my_schema.my_stream",  
    transformation_sql=transformation_sql,  
    dataframe_schema=dataframe_schema,  
)
```
